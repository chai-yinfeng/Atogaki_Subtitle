# 字幕编辑工作面与仓库整理调研

日期：2026-10-20。调研基线：`213d2e6`。状态：**提案，尚未批准实施**。

本轮只研究布局、阅读代码并盘点文件，不改变产品入口、不删除代码／产物，不重新安装 App。静态调用链与数量估算不是 WebKit 性能采样，下面分别标明事实和建议。

## 1. 重新确认用户正在做什么

用户反馈的长字幕卡顿发生在逐段表单式的“字幕粗修”，不是上轮重点优化的高级波形时间轴。上轮索引、窗口绘制与波形缓存不能作为粗修性能已经解决的证据。

从实际操作看，字幕编辑的高频闭环是：定位一句 → 看画面、听原声 → 修原文／译文 → 必要时调整边界或拆分／插入／删除 → 继续下一句。翻译与局部重识别是对选中内容的处理动作，任务恢复、人工编辑保护和可靠导出是底层保证。用户不应为了改几个字或调整一句的时间来回切换“粗修／高级”。

建议保留工作台／收听／学习三个目的区域：工作台处理资料，收听连续阅读与收藏，学习检索和回到来源。合并的是同一任务中的两套编辑界面，不意味着把学习、模型管理、候选参数和导出设置全部常驻在一个屏幕。

“字幕组”在 UI 里优先称为字幕列表／选中字幕，避免让内部 translation groups 变成用户必须理解的新实体。原文修改只改字幕工作区，不像某些视频编辑器那样同时裁切原媒体。

## 3. 可选方案

| 方案 | 布局 | 主要收益 | 主要代价 |
| --- | --- | --- | --- |
| A：固定四区 | 上方视频＋当前段编辑，中间音频时间轴，下方字幕表格 | 所有主要信息始终同屏，适合连续修句和打轴，最接近用户提出的方向 | 笔记本上每块可分配面积有限；需要压缩大标题、外边距和重复按钮 |
| B：统一编辑器＋可折叠面板（建议） | 默认采用 A；视频、音频区可收起，分隔线可调；只改变布局不切换编辑流程 | 支持普通校对与时间调整共用选择、草稿、撤销和播放器；小屏能把空间还给文字 | 需要稳定的布局状态和键盘焦点设计；不应一开始做任意拖拽 docking／多窗口 |
| C：正文校对优先 | 左侧连续双语文本，右侧视频和当前段，底部音频区按需展开 | 适合电台、播客和以阅读为主的语言学习，文本上下文更连贯 | 多选、时间范围和结构编辑不如表格直接；连续文稿容易掩盖 cue 边界，不建议作为唯一编辑呈现 |

建议 B 为统一编辑器，默认保留 A 的四区。若后续确有需要，再在相同组件上提供“文字优先”的布局预设。不要同时重做两个编辑器，或将“文字优先／时间优先”变成两套数据和两套保存逻辑。

默认布局草案：

```text
任务名 · 编辑                       搜索／筛选   处理…   导出…
┌─────────────────────┬────────────────────────────────────┐
│ 视频与一套播放控制   │ 当前段：起止时间、完整原文、完整译文 │
│                     │ 自动保存状态、撤销、上一句／下一句   │
├─────────────────────┴────────────────────────────────────┤
│ 音频波形与字幕块 · 选区／循环 · 缩放                    │
├────┬──────────────┬────────────────┬─────────────────────┤
│ #  │ 起止／状态   │ 原文           │ 译文                │
│    │ 可视范围内的紧凑字幕行；选中行与播放行分别标识     │
└────┴──────────────┴────────────────┴─────────────────────┘
```

1180×760 默认窗口可先以顶部命令区约 44px、视频／编辑区约 230px、波形约 112px、表格约 250px、状态／间隙约 50px 估算，再计系统标题栏；这是线框预算，不是实机完成结论。视频区域约 360px 宽时能保持约 16:9，右侧足够容纳一份双语编辑器。960×640 下不能保证四区均舒适，需允许折叠视频或波形；大字号也必须验证。三小时素材只增加可滚动行数，不增加整个页面高度。

面板内独立滚动，外层工作区不随整份字幕增长。只保留两条主分隔线和必要的横向比例调整；视频正常时始终展示原素材，不重新引入手动切源按钮。

### 交互应同时收敛

- 一个当前编辑段、一份完整双语编辑器、一套播放控制和统一自动保存状态。字幕行只放时间、双语摘要和必要状态；重译、词表修正、插入／删除等按当前选择提供，不在每一行重复一整排按钮。
- `selectedCueId`（正在编辑）、`playbackCueId`（播放到哪）、明确的处理范围和 `timelineViewport`（当前看到哪）分别保存。播放推进不得擅自切走正在输入的编辑段。
- 单击行选中编辑；双击或时间码明确定位播放。提供“跟随播放”与“回到播放位置”；用户自己浏览列表时暂缓自动滚动。
- 多选用于显式批量动作；完整文本框默认只改当前段。批量覆盖人工译文、候选采用和云端音频上传仍保留原有范围／revision／确认边界。
- 重识别、候选历史、待复核问题与词表作为按需打开的工具面板或弹层。默认显示问题数量与定位入口；不把机器运行参数占据主要编辑区。
- 任务恢复进度不与编辑页混在一起；部分原文仍只读，完整识别后才开放现有编辑／收藏／导出能力。
- 任务级翻译／词表和导出仍是任务动作，可从编辑页打开；新建任务已经选择后端时，不必每次打开成品都先落到翻译设置页。具体导航变化须在实施前更新产品方向与 0028 的后继决策。
- 主题保留外围的笔触与材质，编辑表格／输入框减少重复纹理和阴影。阅读对比、选中状态与问题状态优先于装饰，不需要为这轮重做主题系统。

## 4. 粗修页代码审计

| 已观察事实 | 代码位置 | 影响与建议 |
| --- | --- | --- |

| 打开任务默认进入翻译页，但 `renderWorkspace` 仍挂载播放器并生成全部粗修卡片 | 同文件 4387–4427 行附近 | 即使用户尚未打开粗修也承担构建成本；按实际显示面板延迟挂载。统一编辑器后避免隐藏副本。 |
| 每张卡片及每个输入框都叠加阅读纸纹理；部分背景／边界有过渡 | `ui/src/styles.css` 326–328、692–706 行附近 | 是可能增加布局／绘制压力的因素，需实测；不能未经采样声称它是唯一根因。统一阅读底面和轻量行样式。 |
| 字幕全文搜索每次输入遍历全部字幕，并渲染全部命中按钮 | `ui/src/main.ts` 7408 行附近 | 模糊短词可产生数千个节点；搜索结果也应窗口化，使用同一列表筛选并显示命中数。 |
| 两秒全任务刷新没有因进入编辑页而停止；后端逐任务读取含 segments 的快照，卡片恢复摘要还会校验各块原始 JSON 摘要 | `refresh`／`list_persisted_jobs`／`JobSnapshot::load`／`recovery_summary`／`read_evidence` | 与滚动竞争的后台开销。使用轻量摘要、活动任务变化事件或带版本缓存的刷新；完整校验放在恢复／采用边界，不移除可靠性校验。 |

重要区分：`refreshActiveJob` 对已完成任务会直接返回。因此不能说完成的粗修页每两秒都会重建；本次确认的是列表初次全量构建、部分动作全量重建，以及独立的后台全任务 I/O。尚未做 WebKit Performance trace，具体掉帧占比仍需采样。

现有 `SubtitleDrafts`、时间索引、范围采用事务、SQLite cue ID、translation revision 和学习来源应保留，重构界面不重建字幕数据。当前纯 TypeScript／Tauri 可以实现上述面板和虚拟列表；没有证据表明更换框架或桌面技术是必要前提。

## 5. 仓库整理盘点

调研起点 Git 跟踪 278 个文件，其中 docs 84 个文件、53 份决策、约 82 份 Markdown；主路线图已达 476 行、约 78 KiB。跟踪文件中未发现 MP4／WAV／SQLite 任务库／DMG／日志，主要磁盘占用是被忽略的本机产物。

### 能明确整理的小项

额外执行 TypeScript `--noUnusedLocals --noUnusedParameters` 静态审计得到 6 处诊断（当前常规配置未开启它们，不是当前版本类型检查失败）：

- `RecognitionDefaults` 类型未使用。
- `loadAsrCredentialStatus` 函数未使用。
- `startWorkspaceElapsed` 函数未使用。
- `renderSubtitleList` 的 `expandedSegmentId` 参数未使用。
- 单段翻译函数的 `sourceInput`、`translationInput` 参数未使用。

可在独立小提交中审阅清理，随后开启这两个检查防止继续积累。不要直接用删除未使用名字代替交互测试。

### 需要随统一编辑器处理的结构

- `ui/src/main.ts` 7,722 行，包含整页模板、全局状态、粗修／时间轴／收听、翻译候选、学习、设置和追加式初始化。应按编辑会话、播放器、字幕列表、当前段编辑器、音频区、处理工具、任务页及设置模块拆分；一次抽一条边界，保持自动保存和异步取消测试，不作无测试的大规模重写。
- `src-tauri/src/main.rs` 2,987 行，`src/infrastructure/local_db.rs` 5,367 行。可后续按命令域／repository 拆文件；不要连同此次 UI 重构重写数据库语义。
- `karaoke*` 仍是内部历史名称，没有实际 Karaoke 音节功能；在抽出 editor 模块时渐进重命名，不做单独全仓字符串替换。
- 两套 Cargo 根、两个 lockfile 目前是实际构建边界，并非重复垃圾。是否共享 target 或收敛 workspace 需单独检查 feature 与打包行为，不能直接删掉其中一个。

### 可以考虑退役，但不应直接删除的产品残留

`src/interface/web/mod.rs` 仍提供早期 `serve`、health 和带未来计划文案的 Web 外壳；`src/infrastructure/db/` 保留 Postgres 的 user／job／glossary CRUD，仍被 CLI `Serve` 引用。它们有实际入口，不能称为死代码，但已与当前不建设账号、多租户和云端文件托管的产品方向偏离。

建议确认没有现有 CLI 使用者后，独立退役 `Serve`／Postgres，或暂用非默认 `legacy-web` feature 隔离。SQLite 的全部增量迁移、桌面 loopback 媒体服务与这套早期 Web 产品外壳不是同一用途；不能为了移除旧 Web 方案把新的本地媒体服务或 SQLite 迁移删除。SQLx／axum 的依赖精简应以实际 feature 图和许可证重新生成结果为准，不提前承诺明显缩小安装包。

### 文档需要收敛，而不是抹掉历史

- `docs/architecture.md` 仍写“下一阶段已决策、尚未实现”，但 run、检查点、持久候选、翻译依赖已有实现；“当前 provider 按 12 段分批”的描述也混淆语义组与打包请求。
- 产品方向里“识别与翻译质量演进（已确定方向，待实现）”标题与下文的部分已完成实现不一致。当前产品区域仍明确规定粗修／进阶分开；新方案确认前保留，不悄悄改为已采纳。
- `docs/aegisub-capability-map.md` 的推荐顺序仍把已有循环试听、检索等列为下一步；`src/lib.rs` 注释还说“future desktop UI”。
- 路线图混合当前计划、历次试用流水与历史提案。建议缩为当前已发行／本机未发行／下一步／质量门禁四部分，历史详情放验证报告或 archive，并保留原链接／替代说明。
- 增加 docs 索引，明确当前规范、验收证据、研究提案、历史决策各自的权威性。53 份决策是追溯依据，不按数量直接删除；过期决定标记被哪份取代。
- 在线实验分支仍在独立 worktree。其两份决策使用 0045／0046，而当前分支同号已有离线恢复／Gemini 翻译决定；未来合并时需解决编号冲突和交叉链接。本轮不合并、重排或删除该分支。

### 本机空间整理候选

## 6. 建议实施顺序与验收

1. 先确认统一编辑器的默认四区布局、选择与播放关系。将产品方向和 0028 的后继决策同步后，再改变默认入口；本报告不替代批准。
2. 对 10／30／180 分钟、约 300／3,000／10,000 段做 WebKit 采样；统一虚拟列表与单段编辑器，复用已有草稿服务、播放器、波形和事务。若统一布局暂缓，可先延迟挂载隐藏粗修页，避免为了临时缓解再建设第二套编辑器。
