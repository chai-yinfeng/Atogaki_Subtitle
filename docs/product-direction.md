# 产品方向：多语言音视频理解工作台

_最后更新：2026-08-25_

## 项目起点与泛化方向

Atogaki 最初为理解和学习ヨルシカ「後書き」电台而开发：把用户本机已有的节目音视频转成可定位、校对和复习的日中双语资料。这个具体场景决定了第一阶段对日语口语、人名/作品名词表、长节目上下文和时间轴校对的重视。

产品实现不得把某个艺人、节目或语言组合硬编码为唯一入口。日语电台仍是质量基线；在完成该场景的稳定闭环后，Atogaki 开始泛化为处理不同语言本地音视频的字幕识别、翻译、编辑与烧录工具。

Atogaki 是独立的个人开发工具，与ヨルシカ及其官方运营方没有隶属、授权或赞助关系。应用只处理用户在本机拥有或有权使用的媒体。

## 北极星

Atogaki 是一个本地优先的个人工具，帮助中文使用者理解、定位与复习外语音频和视频。字幕导出是结果之一，不是产品的唯一目标。

成功的体验是：听完一段外语节目后，用户能迅速回到任意一句，查看可信的原文与中文翻译，修正重要内容，并把它留作可复习的资料。

## 目标用户与场景

- 希望理解、校对和复习ヨルシカ「後書き」电台内容的中文使用者（首个具体场景）。
- 收听日语、英语或韩语电台、播客和录播节目的用户。
- 观看外语视频、节目和本地媒体的学习者。
- 需要保留双语字幕、片段或笔记供日后复习的个人用户。

首批支持语言组合为日语、英语或韩语识别、简体中文翻译。日语到简体中文继续作为首要质量基线；语言代码、任务存储、字幕轨道和 provider 适配不得假定固定语言组合。

当前日常开发与交互质量基线是 macOS Apple Silicon。Windows x86_64 已有首个未签名 alpha 并进入扩测；它复用共享业务层，在选定稳定候选节点集中更新。韩语体验仍需由实际 Windows 用户完成真实节目闭环后才能宣称成熟；Windows 首版保持 CPU 识别、系统凭据、模型下载、字幕编辑导出和 LGPL 烧录边界，平台 GPU 加速另行迭代。

Windows 基础发行已经以首个 x86_64 alpha 进入扩测；日常主线回到 macOS Apple Silicon，并优先建设学习区 MVP。重新识别仍保留为窄版派生与结果对照能力，但在没有真实识别对照痛点时排在学习闭环之后。字幕编辑效率增强可按真实使用穿插；实时辅助仍是离线闭环和学习闭环稳定后的远期阶段。

Windows 基础发行通过实机闭环后，日常核心开发与交互质量继续以 macOS Apple Silicon 为主；Windows 复用共享业务层，但不要求跟随每个 macOS 开发提交生成安装包。Windows 版本在选定的稳定候选节点集中执行原生编译、安装包、许可证材料和实机回归后更新，避免把两个平台拆成长期分叉的产品代码线。

## 两种产品模式

### 离线精修（第一优先级）

用户导入已经录制或下载到本机的媒体。应用使用本地识别模型生成带时间轴的原文转写，再翻译、校对与导出。

- 优先目标：正确性、可编辑性、可回看性。
- MVP 输入：本地音频和视频文件。
- MVP 输出：双语时间轴、SRT、ASS 和可选的带字幕视频。

### 实时辅助（第二阶段）

实时模式只提供低延迟的理解辅助，不承诺最终准确性。它应录制会话，并在结束后自动运行离线精修以得到最终结果。

- 可接受十几秒级延迟和较粗的转写。
- 优先展示原文粗转写；粗翻译仅作为可选提示。
- 任何实时结果都需要明确标注为“处理中/非最终版”。

## 产品原则

1. **本地优先。** 媒体、模型和任务默认留在设备上；云端翻译仅在用户选择并配置后使用。
2. **离线质量优先。** 不为了“实时”牺牲离线精修的正确性与上下文。
3. **时间轴是一等数据。** 每段字幕必须可定位、编辑、重放和导出。
4. **修正可以积累。** 用户对人名、术语和字幕的修正应进入词表或可复用的学习资料。
5. **媒体来源由用户提供。** 应用处理用户本机拥有或有权使用的媒体，不负责绕过网站限制或下载受限制内容。

内置词表是随 App 版本更新的只读基线；用户第一次编辑时创建独立自定义副本。升级不得覆盖自定义词表或已冻结到任务目录的词表快照。

字幕精修先完善人工时间轴、播放定位和基础结构编辑，再扩展生词／句子收藏等学习模块。学习数据与用于识别纠错的词表保持独立，但必须能从收藏项回到原任务、字幕段和播放时间。

## MVP：理解工作区

MVP 必须完成以下闭环：

1. 导入本地媒体，选择识别与翻译选项。
2. 在后台执行转码、转写、分段、翻译与导出，并反馈进度和错误。
3. 在同一页面播放媒体、跟随高亮当前字幕，并可点击字幕跳转。
4. 编辑原文和译文；原文改动后标记对应翻译为过期，并支持单段或全部重译。
5. 管理并应用词表；导出 SRT、ASS 和双语视频。

MVP 之外的功能：跨设备同步、协作、公共分享、账号体系、云端文件托管和多租户 Web 服务。

## 产品区域与任务内工作流

桌面端顶层只按用户当下的主要目的划分入口，而不是把每一种编辑工具都提升为同级区域：

- **工作台**负责创建任务、查看全部任务历史，并进入单任务的文字粗修、翻译词表和导出模块。普通任务详情不再提供精确时间输入、边界调整或结构编辑；这些操作统一进入任务内字幕编辑。“最近任务”当前就是按时间排序的完整历史；只有真实任务量导致浏览困难时，才增加数量上限、检索或独立历史页。
- **收听**只聚合已经完整翻译的任务，提供跨任务切换、播放位置恢复、只读字幕和悬浮字幕，不放编辑与导出操作。
- **学习**是当前同级区域，承载生词、短语、语法和句子收藏；日语、英语和韩语按来源语言进入独立单词本视图，不混排。外层保持简明译义与来源例句，标准词典在详情中按来源切换。学习数据保持与识别纠错词表分离，并能回到原任务与时间位置。

单任务详情按实际工作流排列为 **翻译与词表 → 字幕校对 → 导出成品**。字幕校对提供播放和逐段文字粗修，并以“进入字幕编辑”打开该任务的进阶工作面；字幕编辑提供波形、精确播放、独立字幕块、Cut／Join、时间轴与文字集中编辑，完成后返回同一任务继续校对和导出。它复用同一 SQLite 字幕主数据，不再作为与工作台、收听并列的顶层入口。

导出成品的基础视觉质量不必等待多人轨道。Atogaki 可以先提供任务级原文／译文命名样式、已安装字体选择、字形覆盖与 fallback 检查、libass 实际渲染预览，以及字体、字号、颜色、描边、阴影、背景、对齐、位置和边距；SRT 明确无样式降级，ASS 与硬字幕保留完整样式。该层服务于可读性和跨平台导出一致性，不开放逐句任意 override 或复杂特效。

多人同时发言、说话人轨道和按说话人区分的字幕样式仍是可能的后续场景。出现真实需求时，应先建立说话人／轨道语义，再把任务级样式扩展为轨道／说话人绑定；在加入逐段排版、运动、旋转、矢量裁切或接近视频软件的能力前，必须重新确认 Atogaki 是继续以外语理解与学习为主，还是扩大为完整字幕制作工具。

## 成功指标

- 用户可以在 10 秒内由字幕跳转回媒体中的指定句子。
- 对一段已完成的转写，修改原文、重译并导出无需重新运行 ASR。
- 本地任务失败时，用户可以看到失败环节与可操作的错误信息。
- 用户的词表能在后续任务中重复使用。

## 决策与变更规则

本目录中的计划是项目长期事实来源。改变目标用户、优先模式、存储策略或主要平台前：

1. 先更新本文件和 `docs/roadmap.md`，说明原因与影响。
2. 若是持久架构选择，在 `docs/decisions/` 新增决策记录。
3. 再开始实现；未记录的探索性代码不得成为默认方向。
