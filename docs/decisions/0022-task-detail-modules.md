# 0022：任务详情按校对、翻译和导出分区

日期：2026-08-14

> 精确时间和结构编辑后来由 0026、0027、0028 迁入任务内字幕编辑；本文的任务详情三分区和粗修职责继续有效。

## 背景

任务详情最初只有播放器和字幕列表，后来陆续加入整批翻译、悬浮字幕、词表修正、字幕导出、视频烧录、时间编辑和结构编辑。所有任务级按钮堆在播放器上方，用户难以判断它们影响当前字幕、整个 SQLite 工作区还是一次独立输出；继续增加学习功能会进一步混合“理解与校对”和“产生文件”两类目标。

## 决定

- 任务详情使用三个一级分区：“字幕校对”“翻译与词表”“导出成品”。切换只改变前端展示，不卸载当前任务、播放器或字幕草稿。
- “字幕校对”包含媒体播放、悬浮字幕、当前句和逐段文字粗修。精确时间、Cut／Join 和结构撤销统一由任务内字幕编辑负责。
- “翻译与词表”包含 provider 状态、整批翻译、任务词表状态、修正规则选择与应用预览。单段重译和“修正加入词表”仍留在对应字幕卡中，因为它们需要明确的段上下文。
- “导出成品”包含 SRT/ASS 导出、Finder 定位与带字幕视频烧录。烧录记录继续使用现有对话框，避免把长列表再次塞入主工作区。
- 返回任务、任务名称与状态、重新读取和任务级操作结果放在分区之外，保证任一模块都能看到当前任务身份和失败反馈。
- 未来的学习功能作为新的一级模块评估，不直接加入“字幕校对”的操作栏；只有必须依赖当前字幕段的收藏动作可以留在字幕卡中。

## 后果

- 现有 Tauri command、SQLite 数据和处理流程不变；这次调整可以独立做界面回归，不引入迁移风险。
- 切换模块时正在播放的媒体不会被强制暂停，未保存字幕草稿也不会丢失；用户仍需在翻译、词表应用和导出前按原规则保存草稿。
- 一级模块为今后的学习入口提供了清晰扩展点，但当前不提前实现收藏、检索或复习数据模型。
