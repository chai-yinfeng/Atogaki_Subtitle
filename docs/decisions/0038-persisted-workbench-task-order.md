# 0038：工作台任务顺序持久化到 SQLite

日期：2026-08-25

## 状态

已采纳。

## 背景

工作台展示完整任务历史。单纯按更新时间排序会让重命名、后台状态更新等操作改变任务位置，也无法表达用户按节目、处理优先级或个人习惯整理任务的意图。只在 DOM 中拖动则会在刷新和重启后丢失，并与收听区的任务顺序不一致。

## 决策

- `local_jobs` 增加可空的 `sort_position`。所有任务尚未手动排序时继续按最近更新排列，兼容旧数据库。
- 用户拖动后一次事务写入当前完整任务 ID 顺序；提交前校验 ID 集合，避免拖动期间新增或删除任务造成部分覆盖。
- 新建任务的顺序值保持为空，因此排在已经手动排序的历史任务之前；下一次拖动会把当前完整列表重新编号。
- 工作台提供拖动手柄，并为键盘用户提供上下方向键移动。收听区复用数据库返回顺序，不单独维护第二份排序。
- 排序不修改任务的业务 `updated_at_unix`，避免把纯界面整理误报为任务处理进度更新。

## 后果

- 排序属于本机工作区偏好，与任务目录中的识别快照分离；移动或重新同步任务快照不会覆盖它。
- 如果拖动期间任务集合发生变化，本次保存失败并刷新列表，不猜测合并顺序。
