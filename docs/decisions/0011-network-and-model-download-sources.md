# 0011：桌面网络配置与可验证模型来源

日期：2026-08-06
状态：已采用

## 背景

打包后的 macOS App 从 Finder 启动，不会执行用户的 `.zshrc`，因此 `proxy_on` 设置的 shell 环境变量不一定存在。模型下载和 DeepL 请求由 Rust 主进程直接发出，不经过 WebView；只提供官方 Hugging Face 地址会让部分网络环境无法完成首次配置。第三方镜像的可用性和重定向策略又可能变化，不能作为没有校验的内建可信来源。

## 决定

- 设置页提供三种代理模式：跟随启动环境中的标准代理变量、强制直连、自定义 HTTP/HTTPS 代理。该设置同时应用于模型下载和 DeepL provider。
- 自定义代理只允许不含用户名、密码、路径、查询参数和 fragment 的 `http://` 或 `https://` URL。非敏感代理地址和模式写入 SQLite；代理凭据不允许写入 SQLite。
- 用户可以选择填写一个 HTTPS Hugging Face 镜像根地址。输入框以 `https://hf-mirror.com` 作为常见可选镜像示例，但不会自动启用、不会替换官方源，也不影响 DeepL。
- 配置镜像时按“自定义镜像 → Hugging Face 官方源”尝试，每个来源的失败原因都保留到最终错误中。界面显示实际尝试来源和重定向后的主机。
- Whisper small、medium、large-v3 q5_0、large-v3-turbo q5_0/q8_0 与 Silero VAD v6.2.0 均固定 SHA-256。任何来源的完整文件只有在校验匹配后才从 `.part` 原子安装；镜像返回错误内容或不同文件时自动尝试官方源。
- 设置页的连通性测试使用当前尚未保存的输入，分别测试镜像（如有）和官方源。点击模型下载会先原子保存当前的非敏感网络草稿，再由下载器读取该配置；这样代理和镜像立即生效，同时不会触发 DeepL 凭据读取。

## 后果

- Finder 启动不再依赖 `.zshrc`；使用本机代理软件时可显式填写其 HTTP 监听地址。透明/TUN 代理仍可配合直连或环境模式工作。
- 设置窗口的后台刷新不得覆盖用户正在编辑的字段；已保存的网络字段可在下载后正常回填。
- 镜像只改变传输来源，不能改变应用接受的模型内容。第三方镜像被劫持、返回 HTML 或模型版本漂移时会被 SHA-256 拒绝。
- 目前中断下载会删除 `.part` 并从头重试，尚不支持 HTTP Range 断点续传。
- 如果代理需要账号密码，当前版本要求在系统代理/TUN 层处理；未来如支持认证代理，凭据必须进入平台系统密钥存储而不是 SQLite。
