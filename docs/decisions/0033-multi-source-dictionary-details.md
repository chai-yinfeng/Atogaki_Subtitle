# 0033：学习列表保持简明，词典详情按来源切换

日期：2026-08-24

## 状态

已采纳。

## 背景

学习区需要同时容纳用户自己整理的简明译义、字幕语境翻译和多家标准词典。把所有结果直接堆在学习列表会压过例句与回听入口；把多家释义拼成一段则会丢失义项顺序、署名、许可证和刷新边界。

英文最初候选为 Cambridge、Collins 与 Merriam-Webster；日文候选为 JMdict 与 Tomoshi。商业来源需要凭据和独立条款，离线来源更适合作为下载到本机的版本化数据包。不同来源的缓存、署名和许可条件不能由一个全局开关代替。2026-08-25 Cambridge 官方邮件确认当前 API 不可用，该候选自此退出当前产品集合。

## 决策

- 学习区外层卡片只显示用户可编辑的“简明译义”、一条来源例句和回听操作。标准词典进入单独详情对话框，不把主列表扩张为完整词典页面。
- 详情上方按来源切换，而不是把所有来源纵向并列：当前英语显示“简明／ECDICT 英中／Collins／Merriam-Webster”，日语显示“简明／JMdict／Tomoshi”。整句收藏只显示简明页；词典来源只用于词、短语或语法选区。
- 每家结果独立保存为 `local_learning_lookup_results`，保留 provider、命中词形、读音／音标、结构化义项、例句、署名、许可证、数据版本、查询时间和可选缓存期限。同一 provider 的刷新只替换自己的结果。
- “简明译义”属于用户学习数据；字幕译文属于来源例句快照；词典返回属于 provider 数据。三者不自动合并，也不互相覆盖。
- JMdict 与 Tomoshi 后续使用类似模型目录的词典包目录、下载进度、固定校验和及原子安装，但保存到正式应用数据目录的 `dictionaries/`，不使用临时测试目录。用户明确触发后才下载。
- Collins、Merriam-Webster 的 Key 按 provider 分开写入系统凭据库，不进入 SQLite、日志或桌面二进制。开发阶段由用户申请并配置；公开发行前再决定 BYOK、正式内容授权或受控代理，不把个人 Key 打进 App。Cambridge 不保留不可用的标签、配置或查询占位。
- 商业 API 的持久化和缓存期限由各 provider 条款决定。Merriam-Webster 只作为独立参考来源展示，不实现质量排名或自动基准比较；正式接入时必须同时满足 Logo、署名、非商业额度和当时有效条款。

## 后果

- 没有下载或配置的来源仍显示稳定空状态，用户可以先理解未来能力，但不会触发网络、凭据访问或隐式下载。
- UI 可以先于真实 provider 交付和测试；后续 provider 只需填充统一结果契约，不需要再次重做学习列表结构。
- 离线词典数据及其衍生数据必须作为独立授权资产审计，不能因为 Atogaki 源码采用 Apache-2.0 就省略 CC BY-SA 等数据许可。
- 多来源详情用于参考和学习，不承诺不同词典义项一一对齐；未来若提供用户选择后生成“我的简明译义”，该动作必须显式发生。
