# 0075：在线翻译校验与组级失败隔离

日期：2026-11-08。状态：按用户确认的异常输出／历史保护与失败隔离方向实施；不更改0072的语义分组、0073的上下文预算或ASR／MT串行调度。

## 已验证的问题

固定8段回放有4条因MT非正常停止而终止；48次返回混入提示结构，其中14次被接受为定稿。正常finish_reason不能证明译文只包含当前源文；异常定稿会进入后续历史。详见[evaluation](../evaluation.md#参考证据台账与当前链路基线2026-11-08)。

## 提示与结果边界

Index使用官方普通翻译请求，参考与规则在前、当前源文作为请求最后的内容。背景以中文字段JSON保存场景、专名、完整历史源译对及后文；保留原文优先、历史译文仅供措辞参考、不复述背景及不补完未完句等规则。8组／2000字符与6000 UTF-8 bytes预算不变，不通过减小音频范围或删除全部历史改善数字。Hy-MT2提示保持。

原instTrans的源文→约束次序作为对照保留：第一轮将背景合入约束后，8条中1条仍回显背景JSON且被初始校验漏过；第二轮前移背景、保留末尾编号约束后，2条回显约束并被拒绝。第三轮用同样8条文本／前置背景／普通翻译请求及末尾原文，8条均返回短译文，无观察到的结构回显；这不是语义质量核验或独立因果消融。原始探针不覆盖。

两种本地后端的响应均先校验，再进入字幕／缓存／历史：非stop、空输出、未闭合thinking、输入原文本身没有的确切提示结构标记，或超过max(300, 6×当前原文字符数)的输出整条拒绝，不截取某个猜测前缀。长度是保守防失控门限，可能误拒合法长译文；标记检查也不能发现所有语义增译。输入原文确实包含相同标记时允许正常翻译，不把任意“背景”词语当错误。

拒绝原因进入translation_error事件，非正常结束时保留实际finish_reason。可取得的拒绝正文只在显式CLI --output的私有translation-rejections.jsonl保存，默认桌面会话不持久保存、不将拒绝正文送入字幕transport。没有自动云端回退、自动录音或离线精修。

## 有限恢复与显示

草稿失败清除inflight，等待新的source/context revision；相同草稿不无休止重试。定稿每个有效group revision最多2次尝试，第一次失败后回到原循环，让已排队ASR优先执行，再取翻译重试；旧revision的失败不消耗新revision预算。

第二次定稿失败发出translation_failed并退休该组，不发布translation_final、不缓存拒绝文本、不将失败源译对放入历史。后续组继续处理；失败组原文仍保留在事件／显示配对中，当前组显示灰色“本段翻译失败”，不认证为白色译文、不遗留旧蓝色草稿。失败终态与正常定稿一样不接受晚到草稿覆盖，窗口重开也保留失败组及对应Qwen原文；控制面板显示部分片段失败提示。既有64组内存恢复上限及可见阅读范围不变，较旧失败可能退出恢复范围。

有终止失败组的worker正常排空，但summary.status为degraded，另记translation_failed_groups和translation_rejections；不能把“会话没有崩溃”计作翻译全部成功。ASR、内部状态不一致等非MT错误仍是fatal。失败组与未完成组、成功定稿分别统计，短重试和所有拒绝耗时保留，不能仅报告被接受请求的速度。
