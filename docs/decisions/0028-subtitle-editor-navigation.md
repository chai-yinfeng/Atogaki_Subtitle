# 0028：字幕编辑是任务内进阶工作面而非顶层区域

日期：2026-08-16

## 状态

已采纳；取代 0026 中把“烤肉”设置为顶层区域的导航决定。0026、0027 的波形缓存、独立字幕块和 SQLite 主数据边界继续有效。

## 背景

“烤肉”是社区习惯称呼，不适合作为面向所有用户的正式功能名称。更重要的是，精确打轴依附于某一个具体任务：用户通常先完成批量翻译和词表处理，再进入字幕校对，必要时切换到专业时间线，完成后返回任务继续粗修和导出。把它与“工作台／收听”并列会割裂该工作流，也让任务详情到编辑器的入口不对称。

## 决策

- 正式名称统一为“字幕编辑”；代码内部已有的 karaoke 标识可渐进重命名，不作为用户界面用语。
- 顶层导航只保留“工作台／收听”。字幕编辑不再展示跨任务任务库，也不提供顶层入口。
- 单任务详情的模块顺序为“翻译与词表／字幕校对／导出成品”，默认进入翻译与词表。字幕校对提供“进入字幕编辑”，字幕编辑提供“返回字幕校对”，两者保留同一任务身份。
- 字幕编辑除时间轴外同时提供当前字幕原文和译文的保存、放弃与会话内保存撤销，避免为修正一句话来回切换界面。
- 离开字幕编辑或切换任务时不得静默丢弃文字草稿；存在草稿时应留在当前界面并提示先保存或放弃。
- 触控板在时间线上横向滑动用于平移，捏合用于围绕指针缩放；普通纵向滑动保留给未来多轨上下浏览，不绑定缩放。波形窗口请求需要短时合并，但不得等到完整手势结束才刷新。

## 后果

- “工作台”继续承载全部任务历史，字幕编辑不维护第二份任务列表。
- 任务详情与字幕编辑形成可逆的任务内导航；导出仍只读取 SQLite 已保存内容。
- 学习区未来仍可作为独立顶层目的评估，不受本次导航收缩影响。
