# 0021：字幕结构编辑冻结 SQLite 段结构

日期：2026-08-14

## 背景

Whisper/VAD 可能把一句话错误拆成多段，或把多句话塞入同一段。普通文字和时间编辑不改变段 ID 与数量，而拆分、合并会创建或删除段；当前任务快照同步会按原始 `segments.json` 的 ID 重建 SQLite 行，因此结构编辑若没有额外边界，会在重新打开任务时丢失。

## 决定

- 第一版结构编辑只提供“从原文光标拆分”和“与下一段合并”，不提供任意多选或跨段合并。
- 第一次成功的拆分或合并把任务的 `subtitle_structure_edited` 设为真。此后原始任务快照仍同步任务元数据，但不再改变该任务在 SQLite 中的字幕段集合、顺序和字段；`segments.json` 继续保留为不可变识别产物。
- 拆分保留左段 ID，为右段生成 UUID；合并保留左段 ID并删除右段。所有段的 `segment_index` 在同一 SQLite 事务内重新连续编号。
- 拆分边界必须严格位于原段时间范围内，左右原文都不能为空。已有译文必须在确认界面中明确拆成左右两份；任一份为空时两段都按未翻译保存，避免把部分译文统计为完整译文。
- 合并只接受相邻索引；时间覆盖两段并集。只有两段都有译文时才保留合并译文；任一旧译文过期时，合并结果继续标记待重译。
- 结构操作记录当前 App 会话内的完整前后快照，并在当前结构仍匹配操作结果时允许撤销。撤销同样是原子 SQLite 写入，不承诺跨重启历史。

## 后果

- 刷新、重启、翻译、字幕导出和新烧录都读取人工调整后的段结构；已经排队的烧录仍使用提交时的不可变 ASS 快照。
- 一旦任务发生过结构编辑，即使会话内撤销回视觉上的原结构，任务仍保持 SQLite 结构冻结；完成任务的原始识别文件不会因此被改写。
- 该边界为以后相邻边界联动、拆分／合并快捷键和波形编辑提供稳定主数据，但暂不实现持久化版本历史或任意轨道编辑。
