# 0060：先对齐重叠区，再选择音频块字幕

日期：2026-10-23。状态：accepted，用户确认“按建议修复接缝，再做片段回归”。

## 证据与原因

对《教父》原片 01:00–06:00 的独立片段，保持 medium／VAD 和其他识别参数相同，仅比较 `max_len=32` 与英文新默认 `0`。两组原始输出均在片段 240 秒接缝包含相同对白，但旧逻辑在每块内部先按字幕时间中点决定归属，再拼接结果。由于左右解码的时间范围不同，同一句话可能被两边同时判为对侧所有，从而在翻译前丢失。

`merged-units`、候选与发布字幕完全一致，只能证明选择后的发布未再丢失，不能证明选择本身覆盖原始对白。旧 `segment::refine` 的字符切分／伪影过滤没有参与此次 Whisper 主流程，不作为本次遗漏的原因。

## 决策

原始音频分块仍为 120 秒加前后 5 秒读取范围；原始证据、模型身份和检查点校验合同保持。接缝选择独立为 `overlap-anchor-v2`：

1. 完整保留相邻块的合法重叠区观测，先在已有单元起点查找唯一公共文字锚点。比较忽略标点、空白和大小写；短 word/token 单元累计匹配，至少 12 个字母／数字字符。锚点还须满足时间范围相交；不把短应答或多处重复当作可靠匹配。
2. 在匹配起点从左侧结果切换至右侧完整观测。切换前检查左侧跨界内容可由右侧连续文字覆盖，且右侧被舍弃的跨界内容已被左侧覆盖；不以公共开头掩盖已识别的独有文字。保留所选原始单元 ID、文本与模型时间，不按字符比例切分或插值。
3. 无法匹配、重复锚点或文字冲突时保留两侧观测，允许暂时出现重复／重叠；记录 `unresolved_preserved`，通过现有 ASR `ManualConcern` 待复核信号展示。它是识别阶段的接缝处理，不是事后自动纠错或自动采用候选。
4. 最终与提前翻译前缀使用同一接缝函数；提前翻译仍留出末块及后文缓冲。`stitching-v2.json` 记录选择方式、锚点、待复核范围和单元身份，局部候选的复核时间加回原片偏移。
5. 原始 checkpoint plan 版本不变，可重用原始识别。新执行不复用旧策略的 final-cues 缓存；Whisper 和 MLX 的派生 cue 策略分别标记接缝版本。已完成工作区不会因打开 App 自动重建，不修改字幕 schema、翻译 ID 合同或数据库事务。

## 替代方案与限制

只改中点为开始／结束时间仍可能因左右时间漂移出现双重排除。直接拼接全部观测虽避免遗漏，但会常态生成重复对白，因此只作无法对齐时的保留行为。重跑整段、强制词级对齐或模型修正文稿会增加计算与内容变更，本次不引入。

精确文字锚点是保守的对齐依据，不是 ASR 准确率保证；双方都漏识别的对白仍不能由接缝处理补造。短片段通过也不能证明整部电影或所有语言质量通过。实际 A/B 与重放证据、尚未执行的人工听辨及翻译验证见[短片段质量基线](../godfather-short-baseline.md)。
