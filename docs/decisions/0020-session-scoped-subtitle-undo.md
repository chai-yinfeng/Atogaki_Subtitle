# 0020：字幕撤销先采用会话内历史

日期：2026-08-14

## 背景

字幕原文、译文和时间轴都可编辑后，误输入可能发生在保存前，也可能在点击保存后才发现。保存前只需恢复 SQLite 当前值；保存后若立即返回，则需要保留修改前快照。完整、跨重启的版本历史还会引入历史表迁移、容量清理、批量翻译边界和恢复界面，当前需求尚不足以证明这套复杂度。

## 决定

- 每张字幕卡提供“放弃修改”，把尚未保存的原文、译文和时间恢复为当前 SQLite 值，不产生写入。
- 每次成功的人工“保存本段”在前端内存中记录修改前完整值及保存后指纹，最多保留同段最近 20 次；“撤销上次保存”把前一份值重新原子写入 SQLite。
- 只有当前字幕仍与该次保存后的指纹一致时才允许撤销，避免重新翻译、重新读取或其他更新之后用陈旧快照覆盖新结果。
- 撤销历史只在当前 App 会话内有效，不承诺跨重启、跨设备或审计用途。未来出现明确的多版本比较需求时，再设计持久化编辑历史。

## 后果

- 常见误操作有即时、低风险的返回路径，又不会提前承担永久版本库的迁移和清理成本。
- 已保存内容的撤销本质上是一次新的 SQLite 写入，因此导出、播放和后续烧录立即使用恢复后的值。
- 撤销会完整恢复保存前的文字、时间和编辑状态标志，包括译文是否因原文变化而过期，保证界面状态与恢复后的内容一致。
