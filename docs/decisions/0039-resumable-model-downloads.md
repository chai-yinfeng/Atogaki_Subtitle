# 0039：模型临时文件持久保留，并用 HTTP Range 安全续传

日期：2026-08-24

> 本决策最初误用编号 0036；2026-08-25 仅为消除与 ECDICT 决策的重复编号顺延为 0039，内容与采纳状态不变。

## 状态

已采纳。

## 背景

Whisper 模型通常为数百 MiB 到 1.5 GiB。此前下载使用 `.part` 临时文件，但 App 启动、请求失败或来源回退时都会主动删除它；网络中断后用户只能从零开始。模型目录和 catalog 已经为每个固定文件记录 SHA-256，因此临时文件可以在不降低完整性门禁的前提下复用。

## 决策

- `<model>.part` 在网络失败、App 退出和下次启动之间保留。用户再次点击同一个模型时读取现有长度，并发送 `Range: bytes=<length>-`。
- 只有服务器返回 `206 Partial Content` 且 `Content-Range` 起点与本地长度完全一致时才追加；服务器返回 `200` 表示不支持续传，此时安全截断并从零写入。
- `416 Range Not Satisfiable` 时先把临时文件作为可能已经完整的下载做 SHA-256 校验；通过则直接安装，不通过则删除损坏临时文件，让下次从零开始。
- 续传前把已有字节重新输入 SHA-256 状态，下载完成后仍对完整文件执行 catalog 中的固定 SHA-256 门禁。校验失败的临时文件必须删除，不能继续累积。
- 镜像和官方源对应同一个固定哈希，因此某一来源中断后允许另一来源从同一字节边界继续。最终文件只在完整校验通过后由原子重命名安装。

## 后果

- 普通断网不会丢掉已经下载的字节；重新点击下载即可继续。第一版不自动在启动时发起网络请求，也不实现暂停按钮。
- 续传开始前需要顺序读取现有临时文件以恢复哈希状态，会有一次本地磁盘扫描；相比重新下载大模型，这一成本可接受。
- 如果上游不支持 Range，体验会退化为原来的完整下载，但不会把旧字节错误追加到新响应。
