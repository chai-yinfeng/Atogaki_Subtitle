# 0006：视频烧录作为独立、可持久化的派生任务

日期：2026-08-05
状态：已采用

## 背景

字幕识别任务与视频烧录的生命周期不同。识别完成后，用户可能继续编辑 SQLite 字幕、使用不同语言轨道重复输出，或取消一次耗时烧录。如果复用识别任务状态，会让已经完成的识别重新变成“处理中”，也无法清楚保留多次输出历史。

## 决策

- SQLite 使用独立的 `local_render_jobs` 保存来源任务、输入、ASS 快照、输出路径、字幕轨道、进度、最终编码器、回退原因和错误。
- 每次提交烧录时，从 SQLite 当前字幕冻结一份不可变 ASS 快照。排队后继续编辑工作区不会改变正在运行的输出。
- 桌面端使用单个有界 worker 执行烧录，避免多个 FFmpeg 任务争用 VideoToolbox、CPU 和磁盘。
- FFmpeg 通过 `-progress pipe:1` 报告进度；取消会终止子进程并清理临时输出。
- 输出先写到目标目录中的隐藏临时 MP4，成功后再安装到最终路径。覆盖已有文件时先保留临时备份，安装失败则恢复原文件。
- H.264 仍遵循 ADR 0005：优先 VideoToolbox，失败后回退 libx264。MP4 不接受源音频编码时，在同一视频编码路径上从 stream copy 回退到 AAC。
- 应用异常退出后，未完成记录在下次启动时标记为失败，不自动重跑；自动恢复留到有真实需求时再设计。

## 影响

- 识别任务保持 `done`，烧录进度和失败不会污染字幕主工作区。
- 同一任务可以保留多次日文、中文或双语输出记录，并看到实际使用的编码器。
- ASS 快照会留在任务目录的 `renders/` 中，用于解释历史输出；最终 MP4 位于用户选择的位置，不归任务删除流程管理。
- 当前单 worker 牺牲并行吞吐，换取更稳定的本机资源使用。
