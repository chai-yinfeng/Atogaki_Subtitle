# 0093 日语句型匹配的有限词槽和语境

日期 2026-11-20。接续 [0091](0091-reusable-grammar-patterns-and-chinese-cards.md) 和 [0092](0092-openjlpt-chinese-and-grammar-prerequisites.md)。

## 规则怎样表达

运行时沿用 Sudachi A 粒度的词形、原形、词性、活用和 UTF-16 范围。用 OpenJLPT 稳定 ID 关联目录、字幕高亮和来源收藏。连续接续规则沿用已有的て形、共同词尾和否定后缀。新规则可以声明左侧语境、核心序列和右侧语境。每个序列支持单词条件、整组可选项、整组备选项和有限词槽。词槽指定可通过的 token 类别和最大数量，也可通过排除条件限制某类 token。

例如「しか～ない」的左侧要求名词性成分，可带格助词。核心从「しか」开始，先容纳有限的论元和副词，再走到谓语的否定。普通否定「ない」和礼貌否定「ませ＋ん」指向同一个条目。动词普通形直接接「しかない／しかありません」时，匹配另一个表示别无选择的条目。「さえ～ば」复用论元和谓语词槽，末端使用假定形和「ば」。接受的长句型包含独立「～ば」时，只显示该长句型中的有效语法含义。「ものの」的逗号列为右侧证据，沿用「来たものの」的高亮范围。

## 匹配过程与边界

规则按 token 推进，词槽从最短范围逐步尝试，核心和两侧语境均满足时返回。允许通过的类别由词槽声明。当前论元词槽上限为 12 个 token，非终止谓语词槽上限为 6 个 token，均为实现参数。标点、引号、未知 token、超出允许词性的成分会中断词槽。这样可在「パンしか買う人が来ない」的连体形谓语前结束搜索。短字幕停顿允许上下文横跨两行，超过 750 毫秒则沿用分段匹配。返回的是核心高亮范围，已有谓语起点和助动词扩展行为用于兼容既有句型。无足够证据时可继续手动查目录。

## 选型及验证

采用 Tsutsuji 的规范形与派生形归并思路，以及 `nnj-grammar` 的核心、语境和有限槽位结构。选择适配现有 Rust 匹配器，保留 Sudachi 分词、现有连续规则和原文范围。直接引入 Lindera／UniDic 会带来第二套形态标注；Hanabira 派生规则的具体许可仍待核对。开发和运行均无需 LLM。[Tsutsuji 相关论文](https://aclanthology.org/L12-1537/) · [参考匹配器](https://github.com/alejoseed/nnj-grammar/blob/dbc22e0e3074c2ee91ecd130ef51805e01ebf851/src/matcher.rs) · [数据声明](https://github.com/alejoseed/nnj-grammar/blob/dbc22e0e3074c2ee91ecd130ef51805e01ebf851/THIRD_PARTY_NOTICES.md)

扩展时先定义可复用的接续条件、许可变体和作用范围，再用真实 Sudachi 结果核对不同词汇、活用和语体，以及相同表面形式但作用范围不同的反例。规则结构、目录与字幕收藏分别回归。首版有 40 个自动匹配条目，和 526 张可浏览中文句型卡独立统计。有限的词法条件仍会遇到省略、缺标点和语义歧义，真实节目上的精确率、召回率待独立标注样本验证。

## 扩展记录

2026-11-20 从 40 扩到 55 个条目。用 LLM 根据既有中文卡和上游接续起草规则与正反例，从共有接续复用「て形」「连用形」「ない形」「た形」规则。新增「ていく／てくる」「すぎる」「やすい／にくい」「づらい」「始める／終わる／続ける」「つもり」「予定」「はずだ」「はずがない」「たばかり」「たとたん」「ないで」「ないでください」和「ずに」。使用本机 Sudachi 核对所有新增卡的捆绑例句，并检查单独准备的高亮、同形词和嵌套用法。模型仅用于开发起草。

Sudachi 把「やすい」「にくい」「づらい」标为形容词性接尾辞，规则按后缀类别和原形匹配。「簡単」「複雑」可得到不同的主要词性，追加词性第三层以识别具有形状词用法的名词，避免把「すぎる」推广到任意名词。从助动词回溯谓语起点时，也会纳入紧邻非自立动词且为连用形的前项，例如「出＋かけ＋ない」。「予定」先覆盖和判断助动词结合的形式。「～方」暂留在目录，因为「使い方」可能作为整词出现，可靠识别需要能区分复合名词中的动词接续和普通的同形词。真实节目识别率继续与目录条目数独立记录。
