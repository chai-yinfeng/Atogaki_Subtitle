# 0014：延迟读取系统翻译凭据

日期：2026-08-06
状态：已采用

## 背景

macOS 的系统 Keychain 在读取通用密码项时可能需要先访问默认钥匙串、再读取具体项目。即使应用层只有一次读取，用户在双击启动 Atogaki、但尚未要求任何云端能力时仍可能看到多个解锁提示。这违背了本地优先首次启动和模型下载不依赖云端翻译的原则。

## 决定

- 启动 App、打开设置、保存非敏感网络配置和模型下载均不得读取系统凭据库。
- 已选择的翻译 provider 以延迟解析方式安装：首次实际发起翻译时才读取 Keychain / Windows Credential Manager / Secret Service；同一 App 进程内结果或错误都会缓存。
- 设置页在未读取系统凭据前明确显示“首次翻译时访问已有 Key”，不把该状态误称为已删除，也绝不把 Key 复制到 SQLite。
- 设置页提供用户主动触发的“检查所选 Key”：只确认对应系统凭据条目是否存在，不回显 Key、不调用翻译 API；检查结果同样进入进程缓存，并修正非敏感的“曾保存”状态标记。
- 用户主动保存或删除 Key 时仍立即访问系统凭据库，这是用户明确发起的凭据操作。

## 后果

- 首次启动与本地模型配置不会被 Keychain 授权打断；只使用本地转写的用户永远不需要解锁翻译凭据。
- 首次翻译或用户主动检查时可能显示一次系统凭据提示；若该操作被拒绝或项目不存在，界面返回可见错误并要求用户在设置中保存 Key。
- 已有安装无需迁移明文数据；延迟加载会在第一次翻译时兼容读取已有的 DeepL 项。
