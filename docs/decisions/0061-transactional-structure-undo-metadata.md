# 0061：事务内结构撤销快照与来源／依赖恢复

日期：2026-10-25。状态：accepted。用户选择“完整恢复来源与翻译依赖；学习收藏沿用现有快照规则”。依据与替代方案见[审计提案](../structure-undo-metadata-proposal.md)。

## 决策

结构操作的后端在实际写入的同一 SQLite 事务中捕获 before／after cue、完整 provenance、翻译依赖和 workspace revision，生成不可由 IPC 反序列化的后端收据。后续会话管理只向前端返回不透明 token／标签及字幕，替换现有数组历史；不增加第二套前端撤销或保存逻辑。

撤销比较完整 expected after 状态及 revision，在一个事务中恢复 cue、来源身份、依赖和过期语义。修订号保持单调；改变或重建的 cue 使用更大修订号，未改变项不回退。依赖仅在原来引用目标上下文当前修订时映射为恢复后的新修订；已过期的历史引用不能被刷新为当前。空任务的结构操作也必须推进 workspace revision。迟到翻译、旧 token 或其他元数据变化必须被拒绝，SQL 中途失败全部回滚。

连续撤销时，只有前一收据 after 与刚撤销收据 before 原本严格相接，才允许把前一收据的 expected after 绑定到此次实际恢复结果；不跳过外部修改，不把旧计数直接写回数据库。收据与恢复结果携带内部身份，防止把其他恢复结果用于重绑定。

学习收藏保留原来的文本／时间快照规则：已解除的 segment 外键不自动重连，未删除引用由既有结构写入 helper 保留。ASR 采用台账、原始证据、人工审查不随撤销删除或回滚，来源只按捕获记录恢复，不按文本推断。字幕 schema、导出格式和源译对应保持不变。

## 分步接入

先给插入／删除增加可记录的 repository 路径和完整恢复／冲突／回滚测试，原路径继续使用同一条事务内编辑 helper。再把时间、Cut／Join、候选采用逐用例接入同一收据合同，并建立唯一有界的后端会话历史。最后替换前端历史为 token，验证全部原生链路、重启失效和内存释放。未接入的旧路径不得宣称已修复；切换前不同时开放两套编辑历史。

每任务十条及总内存预算需用 10,000 段测量后落实，不复制模型、媒体或 ASR 大文件。不能在独立读取后再捕获“之前状态”，不能接受客户端伪造来源字段，也不能靠全片过期掩盖丢失依赖。各阶段小提交、单独验收，本决策不等于整套 token 工作流已完成。

## 2026-10-26 实施补充

recorded Cut／Join 核对 expected workspace revision；时间调整继续核对原 cue 快照。正向结构重建不能依赖原 UPDATE trigger 自动推进修订：统一收尾显式更新受影响源／译修订、手动来源和冻结上下文的机器消费者过期状态，译文被人工替换时解除原机器依赖。旧接口共用操作 helper 但不执行 recorded 收尾，保持兼容。收据与恢复结果提供同一事务状态的 revision／上下文过期 ID，后续 IPC 不需另读数据库凑结果。候选采用和会话 token／UI 切换仍需后续提交。

后继候选路径已共用原范围替换 helper，将来源赋值／采用台账纳入 recorded 事务；记录 after 前不提前提交。候选证据的 ID／起止／原文必须与替换单元一致；沿用旧 ID 的采用保留明确赋予的新 ASR 来源，不按通用手动编辑规则覆盖。来源身份变化本身也推进 source revision 并使冻结消费者过期。撤销恢复旧来源与依赖，采用台账始终保留。此进展仅为 repository 能力，会话 token／应用服务与 UI 迁移仍未完成。

## 会话预算与淘汰规则

同机合成 300／3,000／10,000 段、每段四个 timed-unit ID 和线性上下文依赖的十份真实收据，分别约 7.3／65.3／237.6 MiB。默认以 96 MiB 限制收据、标签和队列槽位的核算容量，每任务最多十条；该样本下可分别保留十／十／四条。核算包含收据 Vec／String 的备用容量，不是进程 RSS 上限，索引节点／分配器、SQLite 与操作中临时快照另计。实际进程测量及限制见[性能记录](../editor-performance-validation.md#2026-10-26结构撤销收据预算)。

全局按最早记录的任务队首淘汰，只删除最老可撤销项；若外部修改打断收据连续性，则从新操作建立新链。单份已提交操作超过预算时不暴露 token，清除该任务旧历史，保留其他任务历史与已提交数据；返回 oversized／discarded 信息，后续 UI 必须明确呈现可撤销范围。不能回退到一个无法跨过未记录操作的旧 token。

StructureUndoHistory 移动持有收据，不复制另一套快照。只允许该任务最新 token 撤销，失败保留收据以重试；成功后用真实结果重绑定前一项，不能重绑定则释放旧链。任务删除／会话清空释放收据与索引，新会话不恢复 token。应用服务必须以同一门闩串行化“写入＋record”和 undo；当前管理器已独立实现，尚未挂入旧 WorkspaceService 或 UI。

## 2026-10-26 共享服务接入

新增 StructureEditSession 持有数据库及唯一共享 Mutex 历史，锁在事务开始前获取，持有至提交后的同步 record；undo 同锁。返回字幕、revision、过期 ID 来自已提交收据，不另读拼接。工作区克隆及切换 provider 保留会话；候选服务显式注入工作区会话，未配置时 recorded 采用在写入前拒绝。Tauri 已完成注入和删除任务成功后的历史释放。

候选采用沿用共同的预检／证据读取和辅助标记 helper，artifact 锁先于会话锁；撤销不获取 artifact 锁。台账与字幕／收据提交后，修复状态或 adopted.json 写入失败只返回 warning，不把已提交结果和 undo token 隐藏为一般失败。旧接口仍保留原错误合同，前端尚未切换；下一步迁移 IPC 和唯一 UI 历史，不把本阶段视为正式 App 已修复。

## 2026-10-26 IPC 与唯一前端历史切换

当前源码的全部桌面结构写入与撤销已走共享会话，旧数组恢复和旧结构写入 IPC 已从注册表移除。前端只缓存最新 token／标签，来源快照只由后端持有。提交／恢复结果同步应用字幕与上下文过期 ID；预算淘汰、超大项及提交后 warning 均显式呈现。文字撤回维持原独立范围。

由于文字自动保存保持单 cue 响应，新增 get_structure_edit_state 按需返回同一 SQLite 读取事务的字幕与 revision，并在会话锁下匹配最新描述符。任务重开时只同步匹配当前字幕的 token；Cut／Join 在 flush 后获取 state，核对等待期间的内容、选段和访问后携带 expectedRevision 提交，后台变更仍由 repository 拒绝。前端 state 请求有代次，旧读取不能覆盖新提交或文字保存。该路径不轮询任务或原始 ASR 证据；新增读取的初始打开／大任务耗时仍属于后续性能门禁。

单元／WebKit 已验证 token-only 请求、连续撤销、重开、文字保存失效、预算／warning 与迟到访问保护；正式和 QA 安装包未替换，新的真实 Tauri／SQLite 原生链路仍待验收，不从合成 IPC 推导已完成原生修复。
