# 0061：事务内结构撤销快照与来源／依赖恢复

日期：2026-10-25。状态：accepted。用户选择“完整恢复来源与翻译依赖；学习收藏沿用现有快照规则”。依据与替代方案见[审计提案](../structure-undo-metadata-proposal.md)。

## 决策

结构操作的后端在实际写入的同一 SQLite 事务中捕获 before／after cue、完整 provenance、翻译依赖和 workspace revision，生成不可由 IPC 反序列化的后端收据。后续会话管理只向前端返回不透明 token／标签及字幕，替换现有数组历史；不增加第二套前端撤销或保存逻辑。

撤销比较完整 expected after 状态及 revision，在一个事务中恢复 cue、来源身份、依赖和过期语义。修订号保持单调；改变或重建的 cue 使用更大修订号，未改变项不回退。依赖仅在原来引用目标上下文当前修订时映射为恢复后的新修订；已过期的历史引用不能被刷新为当前。空任务的结构操作也必须推进 workspace revision。迟到翻译、旧 token 或其他元数据变化必须被拒绝，SQL 中途失败全部回滚。

连续撤销时，只有前一收据 after 与刚撤销收据 before 原本严格相接，才允许把前一收据的 expected after 绑定到此次实际恢复结果；不跳过外部修改，不把旧计数直接写回数据库。收据与恢复结果携带内部身份，防止把其他恢复结果用于重绑定。

学习收藏保留原来的文本／时间快照规则：已解除的 segment 外键不自动重连，未删除引用由既有结构写入 helper 保留。ASR 采用台账、原始证据、人工审查不随撤销删除或回滚，来源只按捕获记录恢复，不按文本推断。字幕 schema、导出格式和源译对应保持不变。

## 分步接入

先给插入／删除增加可记录的 repository 路径和完整恢复／冲突／回滚测试，原路径继续使用同一条事务内编辑 helper。再把时间、Cut／Join、候选采用逐用例接入同一收据合同，并建立唯一有界的后端会话历史。最后替换前端历史为 token，验证全部原生链路、重启失效和内存释放。未接入的旧路径不得宣称已修复；切换前不同时开放两套编辑历史。

每任务十条及总内存预算需用 10,000 段测量后落实，不复制模型、媒体或 ASR 大文件。不能在独立读取后再捕获“之前状态”，不能接受客户端伪造来源字段，也不能靠全片过期掩盖丢失依赖。各阶段小提交、单独验收，本决策不等于整套 token 工作流已完成。

## 2026-10-26 实施补充

recorded Cut／Join 核对 expected workspace revision；时间调整继续核对原 cue 快照。正向结构重建不能依赖原 UPDATE trigger 自动推进修订：统一收尾显式更新受影响源／译修订、手动来源和冻结上下文的机器消费者过期状态，译文被人工替换时解除原机器依赖。旧接口共用操作 helper 但不执行 recorded 收尾，保持兼容。收据与恢复结果提供同一事务状态的 revision／上下文过期 ID，后续 IPC 不需另读数据库凑结果。候选采用和会话 token／UI 切换仍需后续提交。

后继候选路径已共用原范围替换 helper，将来源赋值／采用台账纳入 recorded 事务；记录 after 前不提前提交。候选证据的 ID／起止／原文必须与替换单元一致；沿用旧 ID 的采用保留明确赋予的新 ASR 来源，不按通用手动编辑规则覆盖。来源身份变化本身也推进 source revision 并使冻结消费者过期。撤销恢复旧来源与依赖，采用台账始终保留。此进展仅为 repository 能力，会话 token／应用服务与 UI 迁移仍未完成。
