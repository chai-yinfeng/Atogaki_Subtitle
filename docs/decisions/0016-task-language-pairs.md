# 0016：语言对是任务级持久化数据

日期：2026-08-09

## 背景

Atogaki 的识别参数和翻译 provider 已经接收语言字符串，但桌面任务、SQLite 字段、字幕轨道、导出文件名和界面文案仍假定“日语到简体中文”。只在新建任务界面增加英语选项，会让重启后的翻译、导出、重试和词表应用失去语言上下文，也会继续把 provider 特有代码扩散到应用层。

## 决定

- 使用应用内规范语言代码表示语言，目前包含 `ja`、`en` 与 `zh-Hans`；Whisper 和 DeepL 各自在基础设施适配器中转换为自己的代码。
- 每个任务持久化源语言和目标语言。首批桌面组合为日语或英语识别到简体中文，不在本阶段启用自动语言检测。
- 字幕领域与 SQLite 使用 `source_text`、`translated_text` 和 source/translation/bilingual 轨道，不再使用日文、中文作为结构名称。
- 旧任务、旧 `segments.json` 和旧 SQLite 数据通过别名与迁移读取，并默认解释为 `ja` 到 `zh-Hans`。
- 词表带有源语言；任务只能选择和应用源语言一致的词表。现有词表迁移为日语。
- 面向用户导出的单语字幕使用任务语言代码命名，例如 `.en.srt` 与 `.zh-Hans.srt`；任务目录内部使用稳定的通用投影文件名。
- DeepL provider 在发送请求前显式校验语言组合。未来 Google Translate 或 LLM provider 必须实现自己的语言映射和能力校验。

## 后果

- 英语节目可以复用现有 Whisper、SQLite 编辑、上下文翻译、导出和烧录闭环。
- 日语专用 prompt 和识别修正规则不会误用于英语任务。
- 首次迁移会改变桌面 SQLite 字段名，但保留现有数据和人工编辑状态；旧任务目录仍可打开。
- 自动检测、同一任务多源语言和非中文目标语言仍是后续能力，不通过自由字符串提前暴露。
