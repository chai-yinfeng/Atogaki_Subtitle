# 0029：分离任务处理用时并允许重新定位原媒体

_日期：2026-08-17_

## 背景

任务列表曾使用 `updated_at_unix - created_at_unix` 作为“总用时”。任务在进入单 worker 队列时就会创建，而 `updated_at_unix` 还会被完成、重命名和中断恢复等后续操作修改。因此该差值既不是纯处理时间，也不是可靠的任务生命周期。

任务会把提取后的 `audio.wav` 保存在管理目录，但原视频只保存用户文件系统中的路径。用户移动原文件后仍能听任务音频，但画面和视频烧录无法继续使用。

## 决策

- 任务持久化分别记录创建／入队时间、worker 真正开始处理时间和终止时间。`updated_at_unix` 只表示记录最后修改，不再参与处理用时计算。
- 等待 worker 的任务单独显示排队时间；已开始任务显示运行时间；终止任务只使用开始与终止时间显示处理用时。
- 旧任务没有可靠的开始时间时明确显示“未记录处理用时”，不从旧更新时间推断。
- 当保存的原媒体路径失效时，任务详情提供“重新定位原媒体”。选中文件后同时更新任务状态文件和 SQLite 索引，不复制原视频，不改动已保存的音频、字幕、翻译或人工修改。

## 影响

新任务的处理用时不再受排队、重命名和后续编辑影响。旧任务在信息不足时会失去一个伪精确的用时数字，但不会修改任务结果。原媒体仍由用户管理；Atogaki 只保存可更新引用，因此不会因复制大视频而显著增加任务目录体积。
