# 0032：以收听全文阅读器采集学习条目，并保留来源例句

日期：2026-08-24

## 状态

已采纳。

## 背景

工作台字幕卡以 `textarea` 承担校对，文本选择与编辑草稿、快捷键和保存状态冲突；收听区虽然只读，但当前把整段字幕渲染成跳转按钮，也不适合选择词语。再建立一套仅用于收藏的任务预览会复制播放器、当前句跟随和任务切换边界。

学习条目还需要同时面对两个事实：同一个词可能在多个节目中重复出现；字幕以后可能被修改或任务可能被删除。只保存当前字幕引用会让历史资料漂移，只保存纯文本则无法回到媒体语境。

## 决策

- 不建立第三套任务预览。现有收听区升级为视觉连续的全文阅读器，继续复用同一播放器、任务切换、播放位置和当前句高亮。
- 原文允许选择一个字幕段内的任意字符范围，覆盖词、短语或语法表达；跨字幕段选择首版不保存。时间码和独立跳转控件负责 seek，文本选择不触发 seek。
- 用户选择文本、打开收藏操作或主动滚动时，自动字幕跟随暂停，避免正在播放的滚动破坏选区。
- “学习”成为与工作台、收听同级的资料库，只负责检索、补充译义、查看来源、播放例句和返回原节目，不复制完整任务播放器。
- 学习数据分为“条目”和“来源例句”。条目保存语言对、类型、选中文本、用户确认的译义及可选查询来源；来源例句保存任务／字幕引用、UTF-16 选区、收藏时原文／译文快照和字幕段时间范围。同语言下再次收藏相同选择时可附加来源，而不必复制词条。
- 任务或字幕存在时可以从来源回到媒体；外键删除采用 `SET NULL` 并保留快照，删除任务不抹掉用户已经收藏的学习文本。
- 第一版音频直接引用来源字幕段的开始／结束时间，不把媒体或音频 Blob 写入 SQLite。精确词级音频需要可靠词级时间或手动裁剪，另行评估。
- 词典查询使用独立的 learning lookup provider 契约。收藏和手工编辑译义不依赖网络；未来 JMdict、公共机构 API 或商业词典只能在单独核对许可证、署名、更新和配额后接入，现有字幕翻译 provider 不伪装成标准词典。

## 后果

- 收听区从“整段按钮列表”调整为带独立时间码的语义化文章段落，但 SQLite 字幕主数据和播放器会话边界不变。
- 浏览器选区使用 UTF-16 offset，与 WebView Selection API 一致；收藏时同时验证并保存所选文本快照，offset 不是唯一事实来源。
- 学习闭环可以先离线交付，权威词典的商业授权不会阻塞收藏、例句播放和手工译义。
- 后续若增加间隔重复、词形归一、精确音频或跨句语法，只扩展学习数据与 provider，不反向污染识别纠错词表。
