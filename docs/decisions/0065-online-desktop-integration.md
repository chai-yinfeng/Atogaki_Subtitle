# 0065：在线能力进入桌面的产品边界与整合顺序

日期：2026-11-02。状态：产品边界accepted；下面标明的实施提案仍待讨论。桌面功能尚未实现，不是发行记录。

## 用户已确认

- 研究路线确定：有已验证语言checkpoint时用本地sherpa-onnx Zipformer原生流式草稿；日语用本地SenseVoiceSmall滚动草稿；第二遍定稿统一采用Qwen3-ASR，首选本地MLX 1.7B。翻译独立配置。vLLM继续搁置。
- 推进研究分支向main整合，开始桌面在线ASR与translation能力；研究阶段的“只留CLI”不再是该功能的永久限制，但跑通记录不等于产品已验收。
- 在线首版限定macOS Apple Silicon 14.2+。现有离线功能的最低系统要求保持，不因新增在线采集而整体抬高。
- 从系统音频识别并在独立置顶字幕窗显示，草稿和定稿用不同颜色；独立控制面板负责模型配置等操作。
- 默认不保存录音；用户开启保存后，结束时保留本地音频，由用户手动发起离线精修，不自动创建或运行离线任务。
- 新模型进入离线ASR的选择、下载和推理支持。Qwen3-ASR、SenseVoiceSmall与Zipformer不是翻译模型，不能放入Hy-MT2／云端文本翻译列表。

## 整合策略

以当前main为基线建立 `codex/online-desktop-integration`，合入online研究分支的提交历史，保留main的v0.1.3、编辑器与恢复工作记录。研究源码和证据文档留在experiments／研究入口，不将demo脚本当作正式会话服务。模型、venv、录音和私有转写不提交Git。

研究旧ADR0045／0046与main不同决策重号，将研究两份原文移到 `docs/research/decisions/` 并更新链接；主线原0045／0046不改号。0063／0064保留为当前online研究决策。本次准备整合分支，不直接更新main或替换本机App；待接入方案讨论及相应检查后再形成主线里程碑。

## 桌面实施提案（待讨论，未执行）

### 采集与会话

优先采用Core Audio Process Tap，在14.2+获取系统输出音频；先做系统整体音频并排除Atogaki自身输出，按应用过滤可后置。明确系统音频权限，获取权限前不启动。原生采集与模型进程分离，受管helper的系统要求不传递给旧离线主程序。

Rust负责会话ID、采集时钟、状态、进程生命周期、事件路由与可选录音；模型worker负责推理。普通用户不需要安装Python／uv或启动服务。先复用验证过的MLX实现，以App受管私有runtime运行Qwen；sherpa模型由受管本地worker承载。是否后续改为原生C API／Swift，不在首个接入中重写推理算法。

默认不保存时只保留推理所需的有界内存音频，不自动落WAV临时文件或进入离线任务。开启保存时写入独立会话录音，停止后确认完整文件与时间范围，再提供“创建离线精修任务”。离线精修重新读取录音，与online候选／原始事件分开，不用online定稿自动覆盖正式任务字幕。

会话拥有采集，窗口不拥有采集。建议关闭字幕窗只隐藏显示；在控制面板显式停止，退出App则停止采集并结束自启worker。控制面板关闭时会话仍可运行，必须保留可见运行状态和可返回的停止入口。这一关闭／停止语义尚需用户确认。

### 显示与控制

复用现有macOS NSPanel置顶／全屏覆盖能力，在线显示状态与离线播放器同步状态隔离。一个活动草稿与最近少量已定稿双语段分区显示；草稿使用较淡颜色及“草稿”标识，定稿使用稳定正文颜色，中文在对应定稿后更新。用同segment ID替换，不因迟到结果跳回旧段；颜色不是唯一状态提示。

独立在线控制面板集中展示音频输入、语言、草稿模型、Qwen定稿大小、翻译后端、模型就绪／下载、开始／停止、录音保存开关／目录和保存后创建离线任务。默认按语言选Zipformer或SenseVoice，不展示不支持的语言组合。模型配置建议在下次会话生效，运行中不隐式热换模型。

Qwen和本地MT共用设备调度，避免在线推理与既有离线GPU任务无控制竞争；CPU草稿可独立推进。具体在线优先／离线排队交互在接入调度时讨论，不静默终止已有离线任务。

### 模型管理与离线支持

扩展现有下载／续传／摘要检查与管理UI，以“模型包＋可用runtime＋语言／用途能力”判断是否可选。现有目录以单文件为主，新模型是多文件，不能只追加名字或下载一个ONNX就宣称可用。优先复用现有下载及资源管理，只有实际缺口才新增bundle描述。

离线ASR增加Qwen3-ASR 0.6B／1.7B、SenseVoiceSmall和中／英／韩Zipformer对应checkpoint；Zipformer处理文件时仍按流式状态解码，不宣称变成高精度离线模型。新适配器复用现有task／run／artifact／revision合同。Qwen／SenseVoice第一阶段只能承诺实际取得的片段级范围，不能插值伪造词时间；是否加入Qwen ForcedAligner及相关下载，是精确时间轴需求的后续取舍。

Whisper目录按已确认范围保留small、medium、large-v3 Q5_0、turbo Q8_0；Hy-MT2本地目录保留1.8B。隐藏退役目录项不删除已下载模型，也不使旧任务配置失效。平台不支持或runtime未就绪的模型不呈现为可运行；当前MLX产品接入只针对Apple Silicon，不把Mac结果外推Windows。

## 建议实施顺序

1. 研究历史整合、文档冲突／ADR重号处理和当前产品边界记录；当前只完成到整合分支。
2. 受管推理worker与多文件模型包管理，接离线ASR适配；只验证所选模型路径与相应恢复，不重跑旧研究全矩阵。
3. 原生系统音频采集→内存流→本地草稿／Qwen定稿／翻译的会话服务；先从采集权限和实际音频验证开始，不先堆UI。
4. 独立在线控制面板及置顶渲染，连通segment／revision事件，保留现有离线悬浮播放行为。
5. 可选录音、手动创建离线精修任务，以及对应日常实机闭环；再形成main与本机候选交付。

旧实验与环境当前保留，待新路线完整接入后按既有清理计划统一收敛；不以本次合并为由删除未知数据。云端ASR不因已有Gemini Key自动启用，首版Qwen定稿先走本地；现有云端文本翻译可以独立选择。
