# 0019：人工时间轴以 SQLite 为主数据并允许重叠

日期：2026-08-14

## 背景

Whisper 生成的字幕可以人工修改原文和译文，但开始／结束时间此前只能读取，错误断点会一直进入播放、字幕导出和视频烧录。任务详情又会从不可变识别快照同步字幕，如果只修改前端或临时导出文件，重启或刷新可能丢失修正。

## 决定

- SQLite 字幕段增加 `timing_edited`。人工保存开始／结束时间后，后续任务快照同步保留这两个时间和编辑标记，原始 `segments.json` 继续作为识别产物而不是人工编辑主数据。
- 基础编辑必须保证开始时间非负、结束时间晚于开始时间。与前后字幕重叠时给出明确提示但允许保存，以支持多人同时说话和用户有意叠放字幕；导出层不静默修复重叠。
- 时间编辑与同段原文／译文在一次 SQLite 事务中保存。时间变化不使译文过期；SRT、ASS 和新烧录任务继续从 SQLite 当前状态派生，既有烧录快照保持不可变。
- 第一阶段提供精确输入、取当前播放位置和 100 ms 微调。拆分、合并、相邻边界联动和波形拖动属于后续结构编辑阶段。

## 后果

- 刷新、重启和快照同步不会覆盖人工打轴。
- 用户可以先修正最明显的进出点，而不必等待完整波形编辑器。
- 允许重叠意味着播放器与导出必须按时间判断当前段；未来若展示多个同时活动字幕，需要单独设计，而不能通过禁止合法重叠规避。
