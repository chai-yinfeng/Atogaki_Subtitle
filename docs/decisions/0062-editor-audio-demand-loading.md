# 0062：编辑页音频按需加载

日期：2026-10-28
状态：已接受

## 背景

原生三小时 WAV 诊断确认，暂停进入编辑器、`preload="metadata"` 时 WebKit 请求全文件范围，实际完成文件读取及 body 交出约 124 MB 后提前释放。Range 请求范围不等于实际传输量，Networking RSS 也不等于已收到字节。用户确认“按需加载，减少进入任务时的读取”；接受原生播放器总时长可能在首次操作后才显示。

## 决策

编辑页音频及暂停时的回退音轨使用 `preload="none"`。打开、选段、文字编辑和工具往返不主动加载播放器；播放由原生 play 启动，应用定位则显式请求 metadata。已有播放请求不再被额外 load 中断，连续定位仍使用原来的串行 seek 与末次目标合并。播放中的回退继续恢复位置、音量、静音、速率及播放意图。

保留唯一播放器。未加载时使用其已有 positionMs 边界报告恢复位置／待定位目标；界面跟随、时间轴与处理工具读取该边界，避免未就绪 currentTime=0 把位置重置。退出前仍保存这一目标；不新增持久化位置副本。插入所需总时长可读取当前波形已返回的实际 duration_ms，不用字幕尾部冒充媒体长度。

本决策针对编辑页音频。视频继续 metadata 以提供首帧预览，收听保持原加载策略。波形服务仍独立按可见窗口读取；播放器零 HTTP 请求不等于磁盘零读取。Rust Range／缓存策略不变，不截短客户端请求，也不将音轨改为全量前端缓冲。

## 替代方案与验证

保留 metadata 会维持进入任务时的额外音频读取；对所有视频也延迟加载会影响首帧预览；限制 Range 响应长度会改变现有媒体传输合同。本次采用局部播放器加载策略，不引入这些变化。

播放器测试覆盖未加载退出／恢复、首次暂停定位、原生播放、连续定位、旧元素失效和回退。HTTP WebKit 专项必须在不强制加载的前提下证明打开／选段／重开无请求，以及首次定位／播放恢复；直接设置 native currentTime 的旧测试显式准备 metadata，不能用于证明按需策略。真实 Tauri 同三小时样本的进入、首次定位、播放、恢复与诊断请求量单独验证。
