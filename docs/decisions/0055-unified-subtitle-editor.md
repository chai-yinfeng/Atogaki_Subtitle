# 0055：统一字幕编辑器与四区面板

日期：2026-10-21

状态：已采纳；面板阶段已实现并完成工程验证，用户已确认面板大体正常，并要求修正入口命名及内外间距后继续第二阶段；见 [验收记录](../editor-workspace-validation.md)。取代 0028 的粗修／高级编辑双工作面及默认翻译页导航，保留任务内入口、SQLite 主数据和草稿保护。

## 决策

完整识别且已有字幕的任务默认进入统一字幕编辑器，未完成任务保持进度与只读预览。默认上方左视频／右当前段双语编辑，中间波形时间轴，下方紧凑双语列表。视频和波形可折叠，三处分隔线支持拖动和键盘调整；版本化本机布局偏好跨任务记忆，与字幕数据无关。隐藏视频保留媒体元素及播放状态。

编辑选择、播放当前段、处理范围、时间轴视窗分别管理。单击行选择编辑，双击或时间码定位播放；播放不自动切走编辑对象。搜索与未翻译／过期／待复核筛选作用于同一列表，隐藏当前编辑段时保留编辑框并提示。上一句／下一句按筛选顺序移动。

继续复用 SubtitleDrafts 的 task ID + cue ID 独立草稿、650 ms 自动保存、IME 与恢复冲突保护。文字和结构撤销保持两类，批量能力后置。结构操作先提交草稿，失败或尚在输入法合成时不继续。翻译、词表、导出和候选复用现有应用层用例；工具关闭回到原编辑位置，不重建播放器。

## 替代方案与边界

不继续维护粗修大表单与高级编辑两套界面。正文优先布局可后续基于同一会话增加，不引入第二套保存模型。不更换 TypeScript／Tauri，不做任意 docking、多窗口编辑、多轨、频谱或逐帧精度承诺。

## 分阶段验收

先交付面板与单段闭环，用户验收后再做虚拟列表、轻量任务摘要和 WebKit 性能采样；随后进行系统性模块拆分、文档收敛与产物清理。第一阶段仅抽取布局、选择会话、列表和模板的必要边界，不宣称长字幕性能优化完成。

所有阶段保持 cue ID、translation revision、候选采用校验、学习来源和导出兼容；不改字幕 schema。Web Serve／Postgres 只独立审计，不在本决策中退役。

## 2026-10-21 试用修正

用户界面只称「字幕编辑」，「统一」是实现说明。完整任务直接进入字幕编辑，不先展示任务详情再让用户二次选择；复用已读取详情，避免同一打开动作重复查询。未完成任务显示「任务进度」。翻译／导出是工具面板，只提供这两项工具导航及「返回字幕编辑」。外围与内部采用 4／8／12／16／24 px 层级，桌面编辑器外围 16×24 px，小窗口 12×16 px，工具内容收敛到 12 px。

## 2026-10-21：编辑区居中

按用户试用反馈，将上方改为左侧视频／右侧波形与字幕时间轴，当前段双语编辑移到中间，列表仍在下方。三处分隔线分别调整上方左右比例、上方区域高度、编辑区域高度；视频与波形同时折叠时整个上方区域收起，媒体元素仍保持挂载。布局偏好使用 `atogaki.editorLayout.v2`，迁移 v1 的折叠状态与左右比例，纵向比例按新区域语义初始化。小窗口各面板继续独立滚动。
