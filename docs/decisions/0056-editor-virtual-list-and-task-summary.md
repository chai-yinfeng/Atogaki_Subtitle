# 0056：字幕虚拟列表与任务摘要读取边界

日期：2026-10-21

状态：已采纳，承接 [0055](0055-unified-subtitle-editor.md) 的第二阶段。

## 决策

字幕列表使用 42 px 固定高度摘要行，视口两端各保留 8 行。完整双语文本仍由唯一的当前段编辑框呈现。搜索与状态筛选共用此列表；Home／End 和上下方向键按数据索引导航，不依赖全部行存在于 DOM。移出视口只释放行节点，草稿继续由既有 SubtitleDrafts 持有。

普通文字保存按 cue ID 替换当前数据与时间索引中的对象，不重建时间排序、行索引或全部 DOM。时间或结构改变时重建对应快照索引；有效筛选因文本或状态变化需要重新求值，结果仍只挂载视口行。保留的行节点持续连接，避免失焦保存发生在 pointerdown 与 click 之间时 WebKit 丢弃点击。

编辑已完成任务时停止全任务列表轮询。工作台和收听页改用 `list_job_summaries`：SQLite 任务元数据／计数、检查点范围索引及小型状态文件。摘要不加载 segments 快照、不解析 ASR evidence、不计算原始 provider 文件摘要。检查点进度明确标记为待校验，只用于卡片展示；恢复、部分结果读取和候选采用继续走完整校验。打开任务只检查该任务的新快照，不再同步全部任务。

SQLite 是应用内运行结果的发布源；现有后台执行器继续同步运行中任务。摘要接口不承担外部文件导入或修复职责。保留旧 `list_jobs` 命令兼容性，不改变 schema、revision 校验、SQLite 事务或导出格式。

## 替代方案与限制

不通过分页切断连续导航，不为搜索建立另一份表单，不在本阶段更换前端框架。完整字幕模型仍驻留会话内存；虚拟化约束的是 DOM 和呈现开销，不代表十万段模型、首次未缓存波形或所有处理工具的开销已经消失。小型状态文件读取也不是纯内存接口。

同机测量与边界见 [性能验证](../editor-performance-validation.md)。系统性拆分 main.ts、Rust repository、历史命名与 unused 检查属于下一阶段。


## 2026-10-23：播放时钟避免重复更新静态行

当前行高已由 [0058](0058-compact-editor-and-playback-follow.md) 调整为 28 px。列表的 mark 只在编辑 ID 或播放 ID 改变时写行状态，文字／草稿／筛选／结构变化仍通过原 render／update 刷新。段落时间标题和当前时钟文本只在字符串变化时写入，不重建同一文字节点；不跳过播放头绘制、时间窗请求或新的播放段转换。

同一播放段内反复派发时钟事件，行状态和段落元数据不需要再次写 DOM。固定时刻 UI 回调基线可证明重复写入减少，不能代替原生解码、滚轮 P95 或长期内存验收。回归覆盖固定回调零变更、实际过段／空白跟随、草稿与保存、筛选和节点焦点。


## 2026-10-24：真实滚轮的浏览意图与幂等呈现

手动浏览的意图更新与 UI 呈现分开：每个 wheel／touchmove／滚动条／翻页意图仍使等待中的恢复跟随请求失效，列表已暂停自动滚动时不再次更新控件或查询当前句的筛选归属。跟随按钮的属性、文字及回到播放位置入口只在值变化时写入。播放标记、编辑锁定和虚拟列表滚动绘制继续各自执行。

事件成本通过真实 wheel 输入单独测量，不能用 scrollTop 合成滚动替代该路径，也不能把 wheel 监听器耗时或 DOM 更新数称为帧率。前后源码身份、1 ms 时钟精度与未改善的帧 P95 见[性能验证](../editor-performance-validation.md)。这条可复现的等待恢复竞态不直接视为此前原生偶发锁定的根因。
