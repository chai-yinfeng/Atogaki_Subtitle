# 0049：字幕自动保存、独立草稿与局部候选采用

日期：2026-10-20

状态：已实施，按用户反馈修复数据丢失。

## 保存与撤回

旧界面保存单段后重建整张列表，仅从 SQLite 填充字段，会清空其他段尚未保存的输入。草稿现由 `SubtitleDrafts` 按 task ID + cue ID 管理，不再由临时 DOM 持有；普通校对与高级编辑共用。单段保存仅更新持久字幕快照和状态，其他动作重建列表时也从各自草稿恢复内容。

输入停止 650 ms 后自动保存，blur 立即提交；IME composing 阶段不写入半成品。同段只有一个 writer，保存进行中输入的新内容在返回后继续写入，不用旧响应覆盖新草稿。不同段彼此独立。失败保留输入、错误与重试入口，不无限自动重试。立即保存仍作为显式重试操作，撤回复用每段会话内 20 次保存历史；打轴／结构历史保持独立。

导航前等待 pending writers；窗口关闭事件先等待保存，失败保持窗口打开。输入中的草稿同时在本机 WebView localStorage 保存恢复副本，供异常退出后恢复；SQLite 仍是已提交工作区的唯一来源。恢复时核对现存原文／译文，内容不一致时保留草稿并要求核对后明确保存或放弃，不自动覆盖当前字幕。不保证进程强杀时最后一条尚未写入浏览器存储的按键。

## 选段和采用边界

局部识别优先提供“使用播放头所在字幕段”，按半开时间区间选择完整 cue；空白处不推测最近一句，保留手动范围和当前波形范围。改变范围撤销本次 Gemini 上传授权。Whisper 与 Gemini 共用范围选择，不改变二者原有产品边界。

旧采用事务会对更新后的全片相邻字幕检查重叠，导致范围外既有 ASR 重叠使合法的空白补识别失败。现在候选内部重叠、越界、切穿现有 cue、revision 冲突仍拒绝；只检查新候选与保留字幕之间的实际交叠，不因未修改的历史重叠而拒绝本次操作。范围外 cue 内容、时间、ID 保留。

## 验证

自动化覆盖多段草稿、保存期间继续输入、失败重试、同段并发 flush、跨任务隔离、重启恢复冲突、IME、已有重叠范围外的空白补识别及真实边界冲突拒绝。真实云端 ASR 不在本轮自动回归中调用。
