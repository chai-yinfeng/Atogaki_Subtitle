# 0027：烤肉时间线采用独立字幕块和单轨不重叠约束

日期：2026-08-16

## 状态

已采纳；取代 0019 中“允许同轨字幕重叠”和 0026 第二里程碑中“默认联动相邻边界”的部分。

## 背景

相邻字幕强制共用边界会把本应没有字幕的静音区间填满。它对应专业剪辑软件中的滚动修剪，而不是字幕打轴的默认行为。允许同一轨道重叠虽然可以表达多人同时说话，却会让单轨播放、选择和导出语义变得含糊；多人说话更适合由不同字幕轨道表达。

## 决策

- 每个字幕段是独立时间块，拥有自己的开始和结束时间；相邻字幕之间允许空白。
- 单一字幕轨道内不得重叠。拖动主体会保持时长并在相邻字幕处停止；拖动左右边缘只修改当前字幕，并分别受前后字幕约束。默认操作不移动相邻字幕。
- 当前 SQLite 结构继续视为单轨。多人同时说话出现真实需求后再增加轨道实体和 `track_id`；届时只允许不同轨道之间重叠。
- 时间缩放、时间平移、波形显示增益和轨道高度是不同维度。当前阶段提供连续水平时间缩放／平移和只影响显示的波形增益，不改变音频数据。
- 拆分改为播放头处的 Cut 命令。没有文本光标时可以把原文和译文复制到两块，以保证连续播放时观感稳定，用户随后再整理文字；烤肉区内联拆句作为后续体验增强。连接只修复真正相接的相邻块；存在空白时不自动把静音区间填满。
- SQLite 保存接口继续校验编辑前快照和只修改时间字段，并额外拒绝新产生的单轨重叠。既有旧数据的重叠允许通过编辑消除，但不得扩大或新增。

## 后果

- 空白成为合法时间线状态，不再使用黄色异常提示。
- rolling trim、波纹移动和多轨留作后续显式工具，不能作为拖动默认副作用。
- 旧版本生成的重叠字幕仍可读取；用户修正相关字幕后逐步恢复单轨不重叠约束。
