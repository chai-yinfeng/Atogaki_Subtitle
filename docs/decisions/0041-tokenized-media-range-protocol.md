# 0041：本地播放使用受令牌保护的媒体 Range 协议

- 日期：2026-09-07
- 状态：采用

## 背景

真实长视频的 H.264 画面与 AAC 音轨都能被 FFmpeg 和 macOS 音频框架完整读取，原文件直接播放也有声音，但经 Tauri 通用 asset protocol 进入 WKWebView 后可能出现画面正常、音轨静默。`<video>` 元素没有整体加载错误，因此只在 `error` 事件切换任务 `audio.wav` 无法覆盖该故障。为所有视频生成播放副本会重复占用大量磁盘；默认以两个播放器同步原画面和任务音频则会引入漂移与控制状态问题。

## 决策

- 原媒体与任务 `audio.wav` 在打开任务时规范化路径，并登记到仅存于当前进程的映射表；前端只得到不透明令牌 URL，不得到可枚举的文件协议入口。
- `atogaki-media` 自定义协议支持 `HEAD`、普通 `GET`、单段 Range 和多段 Range。范围响应带正确的 `206`、`Content-Range`、`Content-Length`、MIME 与完整 multipart 结束边界。
- 每个范围最多返回 2 MiB，让 WebView 按标准 Range 连续取流，不把长节目一次性载入内存。
- 播放仍使用一个 `<video>`／`<audio>` 元素和原文件，不生成代理视频，也不改变转录所用的任务音频。任务音频继续作为原媒体整体解码失败时的后备。

## 影响

- 修复集中在桌面取流边界，不修改用户媒体，不增加持久磁盘副本，也不引入双播放器同步。
- 令牌只在当前进程有效；重启或重新打开任务会重新登记。协议只能解析已登记文件，不能把任意绝对路径当作 URL。
- 自动化测试覆盖范围解析、单段内容与 multipart 边界；macOS 安装包仍需用报告问题的长视频执行有声播放实机回归。
