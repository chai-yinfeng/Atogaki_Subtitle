# 0037：多人轨道之前先提供任务级字幕样式与真实渲染预览

日期：2026-08-25

## 状态

已采纳。

## 背景

当前 ASS 和硬字幕使用固定样式，用户直到导出或烧录后才能发现字体不合适、字形缺失、fallback 不一致、字号或描边影响可读性。字体和基础排版直接影响所有导出成品，并不依赖多人说话人语义；如果把全部样式能力都推迟到多轨之后，会长期保留一个高频质量缺口。

另一方面，逐句任意样式覆盖、运动、旋转、矢量裁切和 ASS override tag 编辑会迅速把 Atogaki 扩展为专业特效排版器，不符合当前外语理解与学习主线。

## 决策

- 在多人／说话人轨道之前增加任务级原文与译文两个命名输出样式；现有固定样式迁移为默认预设。
- 第一阶段字段覆盖字体 family、字号、主色、描边色与宽度、阴影、可选背景、对齐、位置、边距和行距。样式属于任务／导出配置，不在每个字幕段复制一份。
- 设置界面枚举当前系统可用字体，检查所选字体对任务实际字符的字形覆盖，并明确显示 fallback 与缺字警告。跨平台按字体 family 解析，不能假定 macOS 字体在 Windows 同名可用。
- 预览必须调用与最终烧录一致的 FFmpeg/libass 字体栈生成代表帧或短预览，而不是只用 WebView CSS 近似；ASS 导出与视频烧录复用同一序列化结果。
- SRT 只保留文本和时间，界面明确提示样式会降级。硬字幕输出已经变成像素，不要求播放端安装字体；独立 ASS 在其他机器播放时仍依赖可用字体。
- 第一阶段不自动复制或打包字体文件。字体收集、ASS/MKV 附件或随项目交付前必须检查字体嵌入与再分发许可，并由用户明确触发。
- 多人轨道出现后，样式模型扩展为轨道／说话人引用命名样式；不改变第一阶段任务级默认样式的兼容性。

## 后果

- 字体选择不是单纯增加一个文本框：需要平台字体枚举、family 解析、字形覆盖检查、fallback 报告、libass 预览缓存和跨平台回归。
- 同一个任务在 macOS 与 Windows 打开时可能解析到不同字体；必须保留原 family 名并显示替代结果，而不是静默改写用户选择。
- 该里程碑提升导出质量但不授权完整 Aegisub 特效复刻；逐句 override 和高级视觉排版仍需新的产品方向决策。
