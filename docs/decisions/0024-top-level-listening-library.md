# 0024：建立跨任务的只读收听区

日期：2026-08-14

## 状态

已采纳。

## 背景

任务详情的三个模块服务于精修、翻译和交付。悬浮字幕与日常“挂在一边听”的行为是跨任务消费场景，把它继续放在单任务编辑页会让信息架构混杂。与此同时，工作台的“最近任务”目前已经是完整历史，新增一页同样的任务列表没有用户价值。

## 决策

- 顶层先提供“工作台”和“收听”，未来把“学习”作为第三个同级区域。
- 工作台继续显示按时间排序的全部任务；在真实数量问题出现前，不创建重复的任务历史页，也不任意截断“最近任务”。
- 收听区只列出状态完成且翻译覆盖完整的任务，字幕内容只读。
- 收听区提供任务切换、媒体控制、字幕跳转、快捷键、倍速和悬浮字幕；悬浮字幕的主要入口从编辑页迁入收听区。
- 每个任务的播放位置以命名空间化的本地设置持久化，切换、暂停及播放过程中节流保存；不上传播放记录。
- 离开收听区、切换任务或进入任务详情时，先暂停并拆除旧播放器；媒体事件和异步任务读取以会话编号隔离，过期回调不得更新当前界面。
- 自动字幕跟随只滚动字幕列表容器，并把当前句放在容器顶部附近。用户主动滚动时临时暂停自动跟随，避免抢回阅读位置或带动整个窗口。
- 任务详情仍保留播放器，供人工字幕校对和打轴，不承担跨任务收听导航。

## 结果

“编辑内容”和“消费内容”具有清晰边界，后续学习区也能独立演进。若任务数量增长，再基于真实使用补充搜索、筛选或历史分页，而不是预先增加重复页面。
