# 0036：ECDICT 先接入可核验的固定基础数据

日期：2026-08-24

## 状态

已采纳。

## 背景

FreeDict `eng-zho` 只有 26,660 个词头，真实查询中连常见词及其规则变形也会因为上游覆盖不足而失败。ECDICT 的英中覆盖、音标、词性、词频与 `exchange` 词形字段更适合学习区，但上游有两组不同边界：仓库中的基础 CSV 约 76 万条；2017 年 `1.0.28` 增强版声称 340 万条，其 SQLite ZIP 约 207 MiB，GitHub Release 没有资产 `digest` 或独立 checksum。

上游仓库当前声明 MIT，但 README 同时说明数据历年汇总自 EDictAZ、考试词表、cdict、WordNet、语料库和网友贡献。仓库级许可证声明不能自动替代对每项历史来源的权利核验。

## 决策

- 第一版接入仓库 `bc015ed2e24a7abef49fc6dbbb7fe32c1dadaf8b` 的 `ecdict.csv`，文件大小固定为 65,933,428 字节，Git blob ID 固定为 `c4ade63ea08cf39d9c3475e96929036d64d94c94`。下载器按 Git blob 的 `blob <size>\0<content>` 对象规则流式复算摘要，通过后才原子安装。
- 不自动安装没有发布方摘要的 `ecdict-sqlite-28.zip`，也不为追求 340 万条覆盖而降低所有词典包的完整性门禁。若上游以后补 SHA-256，或项目独立完成资产审计并固定 SHA-256，可再迁移到 SQLite 增强版。
- ECDICT 继续是用户明确下载的可选数据，不进入 App Bundle。UI 明确显示“基础数据”、固定提交、上游 MIT 声明和混合历史来源提示；这不是对每条释义来源作额外背书。
- 第一次查询把 CSV 的词头、音标、词性和中英文释义写入版本化本地索引；`exchange` 中 lemma、复数和时态等词形作为隐藏查询 form，命中后展示实际词头。中文为空时才回退英文 definition。
- 2026-08-25 用户确认 ECDICT 完全可用，FreeDict 从相邻来源退役：删除下载入口、adapter、测试和相关依赖路径。升级不主动删除用户已经下载的 FreeDict 原始包；共享 SQLite 中的历史派生索引也无需为了升级执行破坏性迁移。

## 后果

- 基础 CSV 比 FreeDict 大约 40 倍，首次建索引会明显更久并占用更多磁盘；后续查询继续走 SQLite。实现按 200 条流式批量写入，避免把约 76 万条全部留在内存，但真实包的首次索引耗时、峰值内存和派生库大小仍必须在发布前测量。
- Git blob SHA-1 在这里用于核对固定 GitHub 内容对象，不等同于上游发布的现代 SHA-256 签名；固定 HTTPS 提交、精确字节数和对象 ID共同构成本轮可追溯边界。公开稳定发行前仍应争取上游 SHA-256 或由项目审计后固定 SHA-256。
- ECDICT 的实用性和法律来源清晰度是两个不同问题。命中率验证通过不自动结束许可证审计。
