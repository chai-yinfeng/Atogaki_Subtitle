# 0002：桌面 MVP 使用 SQLite 保存本地状态

- 状态：已接受
- 日期：2026-08-03

## 背景

桌面 MVP 需要在应用重启后继续列出任务、恢复字幕编辑和保留词表，但媒体与转码产物仍应作为本地文件存在。仓库中已有面向 Web 多用户服务的 Postgres 实验性 schema。

## 决策

使用 SQLite 作为桌面本地状态数据库；任务目录继续保存媒体、音频、字幕导出和 `status.json`。SQLite 保存任务索引、字幕段、编辑状态和词表，不保存媒体二进制。

SQLite 使用独立的 `migrations/sqlite/` 与 `infrastructure/local_db` 适配器。它不共享 Postgres 的用户、认证、文件归属或服务端事件模型。

## 后果

- 桌面应用无须启动或连接任何数据库服务即可运行。
- `status.json` 保留为单任务故障恢复副本；SQLite 成为桌面列表和编辑器的索引来源。
- 云同步、协作或多人 Web 服务可在将来继续使用 Postgres，并通过显式同步边界与本地 SQLite 对接。
