# 0070：双框阅读与独立的ASR／MT前缀提交

日期：2026-11-03。状态：用户确认实施；取代0069的“最近三组定稿＋活动区”布局。

## 显示与提交分开

用户要原文、译文各一个连续字幕框，框内可以同时存在常规颜色的已锁定前文和蓝色的活动尾部。字幕窗中的常规颜色为白色。Qwen完成的ASR段立即锁定，不等待MT；SenseVoice／Zipformer草稿仍可回改。MT使用自己的提交边界，不按ASR白色前缀的字符数裁译文。

每条轨道独立保留约5秒音频范围，按完整单位移动显示起点；活动尾部前的最后一条锁定内容继续保留，方便接续阅读。定稿改变颜色及修改权限，不立即清掉整个框。阅读位置不随旧整组草稿收缩为提交前缀而倒退。3–5秒是软阅读目标，不是定时裁字或模型分段上限：没有逐词时间戳，单个ASR段可到12秒；翻译与识别积压也可能使实际范围更大。轨道最多保留64个单位作为内存保护，与可见历史数量无关。

已有约2秒草稿前缀改写节流继续使用，纯追加／新单位／定稿立即显示；每段用独立span和节流状态，相同文字不重写，锁定span不会随尾部刷新重建。会话切换清空轨道。关闭翻译仍正常推进原文框。

## MT提交策略

每次可发起MT请求时，先检查最早活动组中的连续Qwen定稿前缀：

- 在完整ASR段末查找句末标点。累积源文至少8字符、其后已有至少8字符参考文字时，可以按此边界提交，原因记作sentence_with_lookahead。句号、长度和后文只是启发式，不能证明语义完整；不会重新引入单句号立即冻结「一人で。」的行为。
- 没有合适句末、且组尚未按既有规则封口时，最早Qwen定稿前缀再等待4秒音频时钟后提交，原因记作commit_timeout。只取连续已定稿段，尾部草稿不能因超时变为白色。该等待从Qwen结果被接收时计，不含ASR积压、设备排队与本次MT生成时间，不是E2E保证。
- 既有1.2s停顿、20s／400字符安全上限、EOF仍可封口，并等待所需Qwen revisions齐备。源文选择不拆ASR段内字符，不伪造词级时间戳；句末不恰好落在段末时由后续边界或兜底处理。

提交边界将组拆成两个明确的源文范围：旧group_id只负责前缀，最终译文替换该ID原先的整组草稿；余下ASR段转到新group_id继续重译。一个segment只能被提交一次。尾部在前缀请求执行期间继续变化，不会使已由Qwen锁定的前缀失效；参考后文本身不承诺已最终识别。

请求只将待提交／待重译源文放在Source Text。已提交源文／译文保留为各1000字符以内的滚动背景，后续源文最多500字符作为reference-only背景，要求只输出Source Text译文。提交短句后仍保留有界滚动上下文，避免上下文退化为极短的上一句。缓存键包含源文、既有背景及后文参考。没有用译文字符串公共前缀拼接不同版本，也没有在后端继续生成整段后从展示层硬裁前半段。模型仍可能误译或复述参考内容，需要真实内容人工检查。

## 验证边界

回归覆盖按句拆分、超时不冻结草稿、尾部revision变化、停止排空每段仅提交一次、上下文与Source Text分离、独立着色状态及显示范围推进。普通HTTP请求不涉及受约束解码或模型级前缀保证；锁定是产品提交承诺，超时后无法利用更远未来改写旧译文。默认阈值尚未做质量调优。桌面验证与安装结果见路线图，私有音频／转写不提交。
