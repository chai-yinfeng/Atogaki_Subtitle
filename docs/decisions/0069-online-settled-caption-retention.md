# 0069：分离字幕阅读保留与活动重译窗口

日期：2026-11-03。状态：历史实施记录；其三组列表布局已由[0070](0070-online-independent-prefix-commit.md)取代。取代0068中扩大MT组以延长阅读的策略仍有效。

用户进一步澄清，希望定稿字幕留屏更久，而不是扩大可回改的处理窗口。此前3s／45s／900字符的组使译文长期保持蓝色，并在停止后形成大段文本；最新ASR段与完整MT组并排也容易被误认为对应关系。已确认前后端历史有界，不能据此认定模型完全没有复述参考上下文的问题。

恢复MT默认停顿1.2s、20s／400字符上限，仍跨VAD段合组、整组重译，保留上一组作为参考；达到上限在声学段边界处理，不保证严格不超时。ASR分段、模型及推理请求频率不变。此修正不把每个短ASR段独立翻译。

控制面板和字幕窗统一分为最近定稿与活动区。定稿保留最新三组，原文取该次MT事件的source_text，译文取text；新定稿只增加一组、淘汰最旧一组，不随新草稿变蓝。不启用翻译时保留最近三个ASR定稿。活动区单独显示ASR草稿／等待译文的ASR定稿及可回改MT草稿。两个区域可分别滚动；不靠裁切来掩盖不断增长的处理组。

活动草稿首次出现、新段／组、纯后缀追加立即显示。改变既有前缀的草稿最多约两秒更新一次，使用最新完整快照，不拼接不同版本或承诺永久稳定的MT前缀；500ms轮询也会释放待显示结果。定稿绕过节流。会话切换清除显示状态。相同文字不重写textContent，定稿卡片按ID复用DOM节点，避免轮询重建。

WebView独立保留三组定稿，不依赖256事件传输环中的旧草稿。后端在最近256事件之外最多额外保留三条原文／三条译文定稿，使新打开的窗口也能恢复阅读历史。会话状态携带是否翻译，避免关闭MT时误等译文。事件仍按sessionId／sequence去重和拒绝旧版本，不增加录音、转写或数据库持久化。

验证与安装记录见路线图。本机阅读节奏、前缀节流的主观手感和长节目翻译质量仍由用户体验；不把单元测试或一次桌面运行当作质量／延迟基准。
