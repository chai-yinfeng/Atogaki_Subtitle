## 同片段 A/B 与接缝缺陷

两次调用使用同一五分钟媒体、同一 medium／Silero 模型与相同二进制，运行快照的唯一识别配置差异为 `max_len: 32 → 0`。3 块均使用 GPU，约 83 秒一次；包含配置哈希和处理开销，不作为性能基准。

修复前，旧参数生成 100 段，其中 14 段短于一秒；新默认生成 58 段，无短于一秒的段。最长段两者均约 21.41 秒，仍需时间质量复核。两次 `merged-units → final-cues → segments` 在 ID、文本、时间上逐项一致，但都发生接缝漏选。

片段 240 秒处，新默认左块的同句观测为 237500–243750 ms，中点在界右；右块观测为 235000–244530 ms，中点在界左。旧逻辑同时排除，两侧已识别的内容没有进入最终字幕。旧参数的短切也发生同类遗漏，只是剩余碎片不同。该缺陷发生在翻译之前，不能归因于翻译 chunk 或回填；不表示用户指出的其他错误已全部定位。

实际 `TranslationPlanner` 离线检查：修复前新默认 58 段／50 个语义组，其中 44 个单目标组；旧参数 100 段／51 组，其中 21 个单目标组。新默认前后文字符中位数约 259／252。完整句本身也可能是单目标组，不能据此判断缺少上下文。没有调用翻译 provider，不能推导译文质量或 API 缓存命中率。

接缝修复已按用户选择实施，具体匹配、保留／复核和版本化边界见 [0060](decisions/0060-overlap-alignment-before-acoustic-selection.md)。离线工具 `scripts/audit-asr-publication.py` 核对证据 checksum、发布一致性并列出未选中的跨界观测；这些观测是人工审查入口，不单独视为漏字结论。`cargo run --example inspect_translation_plan -- segments.json NEW-private-plan.json` 使用实际 planner 保存分组而不调用 API。两工具均拒绝覆盖已有报告。

## 后续排查与验收边界

1. 使用相同 medium 模型与 VAD，在隔离目录按新英文默认 `max_len=0` 识别，保存实际参数、模型身份、原始输出及音频块边界；与旧任务 `max_len=32` 的相同原片范围对照。需要严格参数 A/B 时对同一片段另跑旧参数，不能把不同裁剪边界造成的差异归因于 max_len。
2. 对照原音频、ASR 原始证据和内容层 cues，检查文本覆盖、词边界、时间范围、按字符切长句及疑似时间伪影过滤。单独标记块接缝和片段首尾；文本一致不等于识别准确，人工听辨仍需独立记录。
3. 冻结同一份源 cues，再检查翻译组目标、前后上下文、实际 HTTP 打包、返回 ID 与工作区回填；区分源文漏识别、内容层丢失、空译文及语义错位。保留源／译 cue 对应和 revision 合同，不先靠扩大 batch 判断质量改善。
4. 记录真实 HTTP 次数、本地复用、空译文重试、输入／输出 token；补充 provider 缓存命中 token 的观测设计。当前缓存文件数、组日志数均不能直接推导 HTTP 次数或命中率。
5. 接缝策略已按 0060 实施；继续根据失败样本讨论词边界处理、翻译分组／场景上下文、缓存复用的具体修改，分批实现并回归。没有采纳全文上下文或字幕自动修正方案。
