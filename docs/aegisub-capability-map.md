# Aegisub 能力映射与 Atogaki 字幕编辑边界

_调研日期：2026-08-24_

## 许可证结论

Aegisub 是开源软件。项目源码默认使用三条款 BSD 风格许可证，个别目录另有 MIT、MPL 等兼容许可证；官方 README 说明 Windows 和 macOS 成品因为包含 FFTW3 而以 GPLv2 分发。BSD 与 GPL 都是开源许可证，但义务不同：BSD 允许在保留版权、条款和免责声明的前提下修改与再分发；GPL 要求分发相应衍生组合时提供源码并保持 GPL 兼容条款。

FFTW3 是用于离散傅里叶变换的高性能 C 库，Aegisub 用它把音频转换为打轴界面的频谱图。仓库同时保留不启用 FFTW3 时的自有 FFT fallback；“官方成品是 GPLv2”描述的是官方二进制所选择的依赖组合，不是说源码不可见。官方可以发布可执行二进制，同时公开 Aegisub 与对应 GPL 组件的完整源码和构建材料，用户通常只安装二进制，但仍拥有取得、研究、修改和重新编译源码的法律权利。

Atogaki 继续使用 Apache-2.0。可以独立实现 Aegisub 的工作流、交互概念与文件格式能力，但不应直接复制未逐文件确认许可证的代码、图标、文案或品牌。若未来确实复用 GPL 代码或把 GPL 库链接进同一程序，必须单独评估整个分发边界；当前优先独立实现。

- [Aegisub 当前维护仓库](https://github.com/TypesettingTools/Aegisub)：源码与构建事实来源。
- [仓库 LICENCE](https://github.com/TypesettingTools/Aegisub/blob/master/LICENCE)：默认三条款 BSD 风格条款与例外目录。

## 能力分层

| Aegisub 能力 | Atogaki 当前状态 | 建议 |
| --- | --- | --- |
| 字幕表格、文本编辑、拆分／合并、撤销 | 已有任务内字幕编辑、Cut／Join、文字与时间轴撤销 | 继续加强批量选择、复制／粘贴、查找替换和更长历史 |
| 波形／频谱打轴、选择区播放、边界试听 | 已有波形、播放头、拖动／修剪和精确定位 | 优先补 A/B 循环、播放当前块／头尾 500 ms、lead-in/out、提交并跳下一句、相邻边界吸附 |
| 视频定位、逐帧、关键帧／场景辅助 | 已有媒体预览和定位，尚无逐帧与关键帧辅助 | 先补帧步进和“当前帧设起止”；场景检测等真实需求出现后再做 |
| Shift Times、Timing Post-Processor | 只有逐块时间修改 | 适合加入批量整体平移、间隙连续化和最短时长检查，属于高价值编辑效率能力 |
| ASS 命名样式、样式库、实时预览 | 已有任务级原文／译文样式、系统字体检查和 libass 实际帧预览 | 下一步只做真实使用驱动的预设复用；多人阶段再扩展为轨道／说话人绑定，不先做逐句任意覆盖 |
| 可视化排版：位置、移动、缩放、旋转、矩形／矢量裁切 | 未实现 | 位置／对齐可以作为第二阶段；旋转、矢量裁切和复杂 override tags 会把产品推向完整特效排版器，暂缓 |
| Karaoke 音节打轴与模板特效 | 未实现 | 歌词学习若形成真实主场景，可先做音节时间；模板特效与高级 ASS 动画保持远期 |
| Translation Assistant、拼写检查、词库 | 已有双语任务、翻译 provider、学习词典 | 结合 Atogaki 强项做“原文／译文连续校对 + 提交并下一句”，比复刻通用翻译助手更有价值 |
| Lua Automation、宏、导出过滤器 | 未实现 | 生态价值高但安全、API 稳定性和兼容成本很大；主线成熟前不引入 |
| 字体收集、附件、分辨率重采样、多格式兼容 | 已有字体枚举、任务字符覆盖／fallback 检查；不复制字体 | Windows 实机验证后再评估字体附件；附件打包涉及字体授权，完整格式工作室放到定位复核之后 |

## 推荐推进顺序

第一阶段保持“外语理解工作台中的高效字幕编辑”，吸收 Aegisub 最有价值的打轴闭环：

1. 当前字幕块选择区、A/B 循环和头尾试听。
2. 可配置 lead-in／lead-out、毫秒／帧级 nudge、提交并自动跳到下一块。
3. 多选字幕块整体平移、批量时间检查、相邻边界吸附。
4. 原文／译文双栏连续校对、查找替换、未翻译／过期筛选。
5. 任务级原文／译文命名样式、字体检查与 libass 视频预览；多人阶段再绑定轨道／说话人，不开放任意逐句特效。

这能覆盖日常听写、翻译和打轴的大部分高频操作，同时保留学习区和本地理解闭环的差异化。完整 ASS override tag 编辑、矢量排版、Karaoke 模板和 Lua Automation 应视为另一条“专业字幕制作套件”产品路线；启用前需更新产品方向和架构决策。
