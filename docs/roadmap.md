## 当前优先：按持续中文预览的 2 秒目标验证预译链路

2026-11-15 用户确认五段校正文本的 H/G 按标点切分保留意思，九次 Hy-MT2 中文结果总体可接受；指出「オイラン」未译成「花魁」。加入确认前文总体略有帮助、影响较小，很多结果一致。按整体反馈记录，不编造逐项评分或总体准确率，不再沿用助手此前更严格的待核对判断。R/F 仍为空，原输入和输出不改写，反馈绑定原结果摘要留在私有目录。

用户确认后续顺序：先对照现有 Python／MLX 和 Voxt native MLX，不开投机解码，再评估 DFlash；当时 DSpark／Metal 支持待核验，后继隔离结果见下文。第二阶段只用[校正文本基线](../experiments/online/datasets/japanese-radio/confirmed-text-baseline.json)中的五个既有裁片，不恢复未校正模型结果、英语／湖吉或整段候选池，不新增录音功能。原文本测试条件继续单独保留，ASR 输出不反写人工原文。

已固定 Voxt 2.0.3 的发行源码，按官方脚本在忽略目录完成 native runtime 构建，原 App／Python 环境保留。对照控制 MLX 0.32.3／0.32.4、FP16／BF16、reference／voxt_swift 布局；不将不同计算精度、预处理与停止规则的差异全部归因于应用语言。实验边界、结果与后继门禁见[当前评测合同](evaluation.md)。五臂各三轮共 75 次全部完成；native reference 与同版本 Python BF16 的五段文字完全相同，后两轮总计算时间均值约低 8.7%，但 MLX 峰值分配更高。voxt_swift 布局引入三段文字变化，关键误听仍存在；小样本不能推导准确率、稳定提速或字幕 SLO。该无投机阶段没有开启 DFlash／DSpark。这不是生产 runtime 迁移，也没有运行 Voxt App 或云端请求。

后继已按用户要求完成 native DFlash：同一主模型／MLX／停止规则，每种布局重跑 baseline 与原始 BF16 draft，四臂各三轮共 60 次正常结束。voxt_swift 后两轮五段总计算时间均值 4.449 → 3.050 s，MLX peak active 3.295 → 4.021 GB，两段文字变化；reference 为 4.335 → 2.949 s、3.291 → 4.016 GB，五段文字相同。它证明该小样本有约 1.46–1.47× 计算加速，不证明在线字幕延迟或语义质量通过。

初次 Python 兼容性探针确认现有包不能直接加载专用 DFlash／DSpark；用户随后明确确认隔离适配，先 DFlash、再 DSpark，并保留 Python 路线。已在 experiments/online 增加目标 taps、专用 head、词表映射、block verify／KV 回退、confidence 记录和有限性拒绝，复用原音频处理及模型层，不修改生产包。实验和边界见[第四阶段](evaluation.md#第四阶段python-专用-head-适配2026-11-15)。生产链路与录音保留项不变。

最终同五段裁片、两套 target 条件、原接口／无 draft／DFlash／DSpark 各三轮，共 120 次均 EOS。当前 MLX 0.32.4／target FP16 条件下，无 draft 总计算均值 4.619 s，DFlash BF16 2.870 s，DSpark BF16 5.607 s；MLX peak active 为 2.829／3.555／3.583 GB，五段文字均与原接口一致。0.32.3／target BF16 控制复现 DFlash 加速，DSpark 较慢且一段文字变化，不据此宣称质量改善。DFlash 值得进入后继链路验证，DSpark 暂不晋升，不切换 C++／Rust／Go。

首次将 DSpark head 转成 FP16 导致输入 FC 溢出；失败及数值审计保留，最终保留原始 BF16 head，并对进入 head 的 target 激活显式转换。真实失败回归确认非有限 head 会中止，而非静默逐 token 兜底后冒称成功。新增合同验证与现有 Python 回归共 177 项通过；这不等于实时字幕、取消、长时内存或 ASR／MT 竞争验收。oMLX 前缀复用、缓存观测和内存管理仍为用户确认的后置研究，先验证已有 llama-server 能力，不在本轮增加另一套服务。

用户随后授权验证单路 Qwen＋DFlash 持续预览／锁定／MT。同五段裁片按 1× 连续到达、约一秒刷新，单路无 MT／单路＋MT／受控双模型＋MT 各两轮完成；复用现有音频、事件和阶段互斥，新增实验邮箱及回放入口，不导入生产。30 条原文定稿与整裁片结果一致，20 条译文完整，无迟到回写、preview 需求覆盖或遗留线程。单路＋MT／双模型＋MT 首次原文中位数 1.601／1.090 s，原文锁定距 EOF 为 0.852／1.040 s，最终译文为 1.415／1.425 s；Qwen 每轮计算 20.837／4.897 s，主要代价是反复重算。五段最长 13.926 s、已知 EOF 边界及 final-only MT 不能代表自然直播、长时内存或完整 App SLO。下一步先讨论重算控制与锁定合同，不据此移除 SenseVoice；详情见[第五阶段](evaluation.md#第五阶段单路-qwendflash-的持续预览验证2026-11-15)。

后继只读补算相同 revision 的“原文锁定 → 译文完成”，单路／双模型中位数 0.417／0.384 s，不能用上一张表两个中位数相减。已安装 MLX 包已有完整约 8 秒音频块的 encoder／音频前缀 KV 缓存；该次补算时 DFlash 实验尚未接入，提出核对全局 mel 归一化、尾帧、target taps 和 draft cache 一致性，不能把四倍重算当不可避免。先研究已有能力与保持文字可修订的方案，未直接开启带文字强制前缀的 streaming 路径；云端 API key／流式译文当时为讨论方向，后继确认见下文。

用户确认继续优化后，已在隔离入口复用完整音频块，新增同边界的 target／DFlash context KV 快照，不保存旧文字、不改归一化／注意力块／分组。固定原 47 个前缀、四轮 188 次文字／token／结束原因一致，累计计算均值 20.118 → 18.423 s，主要节省 encoder／prefill。后继缓存关／开 × MT 关／开各两轮 1× 回放完成，40 条原文定稿、20 条译文及因果／revision／互斥／清理核对通过；带 MT 时 Qwen 每轮计算 21.171 → 19.764 s，锁定距 EOF 中位数 0.848 → 0.668 s，译文 1.411 → 1.206 s。锁定后的 MT 仍约 0.40 s。首次阶段仪表错误已保留、修正并在新目录重跑，不使用无效阶段占比。见[第六阶段](evaluation.md#第六阶段完整音频块与-dflash-kv-缓存2026-11-15)。

当前仍是连续输入／跨区间队列流水线，单次识别完成后发布原文，MT 完整返回；共享 GPU 默认按任务交错，未启用物理重叠或 batching。用户明确云端设计为原文待译组锁定后请求一次、流式接收响应，不随每次原文更新重复请求；实现和调用仍未开始，不改变本地默认预译合同。后继优先依据阶段成本讨论剩余重生成与锁定规则，再确定是否另测并发；自然边界、长时资源和失败恢复仍是晋升门禁。

用户随后将理想延迟补充为 2 秒以内，授权分别测试刷新率、边界及文字锁定。相同五裁片、缓存开启、MT 整裁片一次，0.5／1／1.5／2 秒刷新及单独的前缀末尾 5 tokens 可改各两轮完成，共 50 原文定稿／50 译文。刷新臂最终 tokens／中文相同；首次非空原文中位数按 1 秒基线、0.5／1.5／2 秒分别为 1.447／1.270／1.802／2.278 s，最大 1.760／2.199／2.043／2.469 s。0.5 秒将计算从 20.115 增到 32.327 s，每轮 7 次待处理预览覆盖，不能只靠更快刷新实现更低延迟；2 秒刷新不足以满足该批首次原文目标。保留 1 秒为实验参照，不当作连续正确译文的 SLO 验收。

后继用户明确 2 秒指“说话期间持续看到可修订译文”。本批 final-only MT 不覆盖这个目标，以上首次原文数字仅为诊断，不能据此选定产品策略。下一项先在已有可修订预译链路观察中文内容与资源竞争，不把 EOF 后约一秒返回当作持续字幕已达标；当前校正文本无逐字声学时间，质量时钟还需要可复核内容锚点。云端一次请求只负责锁定后交付时，长句预览仍需本地预译或另定义受控云端更新；两个候选未选定，也未直接实现混合方案。

文字前缀臂计算约降 30%、译文距 EOF 中位数 1.256 → 0.861 s，但两轮均改变同三段最终原文；质量复核保留私有 `review.md`，未开启默认。边界复用当前 VAD，在五段只找到一个内部切点；全样本保留的完整／切段对照 22 次均 EOS，平均总计算 2.868／2.958 s，没有明确收益，原文与中文也发生变化，不能据此选择自然语义边界。186 项回归及引用／fmt／diff 通过，11 个自建服务均退出。结果与当前能力边界见[第七阶段](evaluation.md#第七阶段刷新文字锁定与边界影响2026-11-15)。

云端只完成官方资料与 Voxt 固定源码核对：一次请求可以携带谨慎校对和翻译要求并流式返回，但纯文本模型不能补回未输入的声学证据，当前本地 MT 本身约 0.38 s，也不能预设云端更快。后继若实测，仍固定已校正 G/H，并分别记录首内容／首个可读片段／完成时间、语义与 token 费用；音频直译是独立路线。本轮没有接入账户、请求 API 或上传材料。

原 evaluation 页面及素材角色／离线／runtime 提案已[整体归档](archive/2026-11-14/evaluation-before-confirmed-text.md)，引用保留；screening 只解释历史候选，不再决定当前名单。

## 2026-11-13 电台 Qwen 候选筛选
