## 2026-11-14 在线确认模型默认收敛

用户确认采用 Qwen3-ASR 1.7B MLX 8bit 作为在线确认识别默认；控制面板首次选择和模型目录优先级收敛到此档，手动选择的其他可用模型在刷新时保留。两档 0.6B 及原始 1.7B 继续可选，不删除包或改动离线任务。已核验的 8bit 包克隆至现有受管目录，不改数据库或旧 manifest；App 安装包暂未覆盖。决策见[0079](decisions/0079-qwen-17b-8bit-online-baseline.md)。

完整 worker 按桌面默认 SenseVoice／Silero／Hy-MT2 1.8B、空词表和场景、预译开启，对 Vol.34 前 10 分钟和 radio-06 三分钟做 1 倍速回归：150 条确认原文、83 组最终译文，漏确认／拒绝／失败／未完成均为 0，源段覆盖和 revision 检查通过。ASR 返回距音频末尾 p95 分别 2.192／2.271 秒，译文定稿距组内首段末尾 p95 为 11.058／10.586 秒；这不含真实采集／原生绘制，也不是与此前 Index 实验的同条件 A/B。抽查仍见 ASR 误词传播及 MT 无依据改写，语义质量未验收。完整条件、产物和验证见[回归记录](qwen8-online-regression-2026-11-14.md)。

随后只读核对 Voxt 2.0.3：默认模型和本项目的固定 revision、9 个文件全部一致；产品工程重点为预览／停止后确认、长录音后台处理、解码停止、512 MB freed-buffer cache 限制、进程监督和音频恢复，另可选约 726 MB 的 DFlash 辅助解码包。上游主要为中英文合成语料，不能证明连续日语电台翻译达标。后续保持基线，先定位语义失败；runtime 准备闭环参考这些实现，native／DFlash 的迁移需另做同条件比较，未在本轮实施。见[源码评审](voxt-local-asr-review-2026-11-14.md)。

补核翻译：该固定提交的内置本地 LLM／Hy-MT2 已退役，Translate 实际调用用户配置的语言模型 API，可为云端或另行运行的 localhost 服务。旧本地模型评测不能作为当前 App 的默认后端证据；评审文档已修正。

## 后续工程与质量目标：待评估，未实施

用户要求把重复计算和内存增长纳入工程线：基于固定电台回放，分别观察 Qwen、SenseVoice、MT 的耗时和驻留、MLX active／cache／peak、系统内存压力／swap，以及随片段增长或反复识别发生的变化；进程 RSS、模型文件大小和统一内存分配分别报告。先确认成本来源，再评估窗口重算、缓存上限、任务合并及生命周期，避免只遍历等待／量化参数。此前 0076 已实现原文时钟分组、需求合并、阶段交错及共同停止预算；0059 模块抽取主要改善维护边界，两者不都算性能提升，也不代表长时内存已优化完毕。

保留“投机解码加速的 Qwen 预览／确认”和 DSpark 为候选实验，尚未替换 CPU SenseVoice 或接入 native runtime。token 级 draft／verify 与产品两遍识别分开评估；比较包括整体延迟、GPU 与 MT 竞争、额外内存和目标模型输出一致性，不能以 tokens/s 代替在线收益。

用户期望一个相对稳定、接近当前离线翻译的实际质量目标，而非完全无错。后续讨论以未经人工修改的当前离线流程作整套产品参照；需要定位在线分段／上下文的额外损失时，另设同 ASR／MT 的离线对照。关键事实、否定／比较、人物关系及增添内容优先于表面字词一致，ASR 残余错误、MT 对当前原文的错误和分组／上下文造成的额外损失分开记录。具体门槛与实验方案仍待讨论，本轮不改变已选模型、等待策略或产品验收标准。

## 2026-11-13 电台 Qwen 候选筛选

按用户确认的实验设计，冻结 Vol.1／Vol.34 各 3 分钟，经当前在线 VAD 规则形成 63 个同输入请求。四档 Qwen 各两轮反向顺序串行 Metal 运行，共 504 次调用、502 次完整；0.6B 4bit 同一片段两轮都触发 token 上限截断，失败保留。1.7B 8bit 每轮总计算约 33.4–34.6 秒，原始 1.7B 为 53.9–55.1 秒；MLX 进程峰值分别约 3.23／8.16 GB，不是 App 总内存或在线延迟。

同一模型两轮文字一致。1.7B 两档有 7 / 63 段归一化文字不同，不能解释为准确率。另用已安装 Whisper Medium 对同一批 63 段生成辅助参考。私有材料保留原始 63 段／22 段优先清单，并生成含全部 7 个量化分歧、1 个截断和 2 个一致控制的首批 10 段听审页，支持本地播放、匿名评分与 JSON 导出。

已收首批 10 段／40 个判断：1.7B 8bit 为 9 个可接受／1 个关键错误，原始 1.7B 与原始 0.6B 均为 7／3，0.6B 4bit 为 6／4。这是刻意挑选的实用可接受性反馈，不是总体准确率或翻译质量。当时建议采用 1.7B 8bit、未改默认；后继默认收敛及回归见上文 2026-11-14。导出原件／备注原样保留私有目录，含不确定处的建议原文不自动升为逐字 gold。实测、命令及统计边界见[实验记录](qwen-radio-candidate-screen-2026-11-13.md)。

## 2026-11-13 模型分类与按需候选

模型管理按转录、草稿识别、翻译、VAD 折叠，转录内按 Whisper／Qwen 展开。默认突出 Whisper Medium，其他 Whisper 和原始 Qwen 1.7B 保留在可选项；Hy-MT2 7B 退出新下载入口，已有受管模型保留选择／卸载，不删除本机资产。新增 Qwen 0.6B BF16、0.6B 4bit、1.7B 8bit，原始 1.7B 包复用既有路径；目录记录固定 revision、大小和逐文件 SHA-256。

多文件包逐项续传／校验后从暂存目录整体安装，在线控制面板共用已安装包；不再依赖私有 manifest 才能列出模型，缺文件或大小不符不标就绪。草稿／在线 ONNX VAD 先显示状态并注明随本机环境准备；新机 runtime 分发、草稿独立下载、Qwen 离线 provider 和量化后的真实质量／性能仍未交付。在线默认值与分组／修订策略未变，未自动下载权重或覆盖本机 App。决策见[0078](decisions/0078-model-categories-and-qwen-packages.md)。

验证：Tauri 40 项通过／4 项依赖本机词典或凭据的忽略，前端 372 项通过；生产类型／构建、两套 fmt 与 diff 检查通过。WebKit 模型视图／设置操作验证分类默认折叠、展开后 Medium 优先、Qwen 下载／卸载入口、网络与路径草稿保护及焦点稳定；1120／460 像素生产布局已检查。下载回归使用本地 HTTP 小型合成文件，覆盖损坏校验、续传、取消、完成／取消竞态和完整目录发布；未运行新量化模型的实际识别或性能测试。610 个相对 Markdown 文件引用无缺失。

## 2026-11-13 暂停 Windows 维护

用户确认当前项目暂不考虑 Windows。两条 GitHub Windows workflow 已在仓库端停用，源码移除 push／pull_request 自动触发，仅保留将来显式启用后的手动入口。此前 main 的 e085fa8／6c8e21d 推送各触发一次 Windows compile failure，邮件与这两次运行对应；没有在途运行需要取消。既有 Windows 源码、脚本、配置与发行记录保留，不扩 Windows 回归。决策见[0077](decisions/0077-pause-windows-development.md)。 YAML 加载与触发器断言、原 job／手动输入保留核对、两套 fmt、diff 与文档引用检查通过；未运行 Windows 编译或修改程序行为。

Release／DMG 用户安装方式保留。runtime／多文件模型准备的目的为补齐新机器上 App 自管依赖；未批准新的自动更新器、用户手动 Python 服务或模型默认值变更。用户希望 ASR 下载接近 1 GB，后续按体积、工作内存与日语质量筛选量化候选，不将现有 1.7B 全精度约 4.7 GB 冻结为发行默认。当时识别到 Hy-MT2 7B 的目录残留，后续按上文 0078 收敛入口，保留已下载文件和原有选择。

## 2026-11-12 在线控制与阅读界面

## 下一步与验收门禁

1. **观察在线 UI 日常使用。** 已完成主线收拢和控制语义／布局修正；按具体反馈继续改善阅读，不把源码与 WebKit 验证当已完成原生使用验收。
2. **沿用在线结构做实现优化。** 正确性优先，允许数秒到十几秒；保留 two-pass、分组、revision 与阶段调度。后续可参考 Voxt／native MLX 的内存、重复计算及推理实现，不继续寻找新的顶层 pipeline，也不在本轮更换 runtime。
3. **补齐 runtime／模型准备。** Qwen 多文件管理已实现；本机导入脚本仍不能代替新机器安装闭环。Python runtime 分发、草稿独立准备或 native MLX 替换仍需按各自方案推进，不能由本次目录整理视为完成。
4. **离线与学习维持使用闭环。** 根据具体反馈改善收藏、回原句、Anki 及日常交互；不自动建设内建复习系统。
5. **按里程碑回顾需求。** 在线有可信对照、学习有一轮使用反馈或发行前再更新同类工具对照，不新建周期自动任务。

本次新识别的维护问题包括：跨分支“当前状态”容易混淆；旧提案与执行流水会重新进入待办；默认构建仍携带早期 Web／Postgres；部分入口／服务集中协调较多。前两项本次文档整理处理，后两项保留为设计议题，不视为已授权代码变更。
