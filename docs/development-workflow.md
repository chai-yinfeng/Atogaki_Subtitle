# 开发协作与回归约定

_最后更新：2026-08-03_

本文件的可执行摘要位于仓库根目录的 `AGENTS.md`，供后续开发 agent 自动遵守；本文件解释项目层面的意图。

## 开发节奏

- 每个可独立理解的进展完成后创建一个小而完整的 Git commit。
- commit 完成并通过相应回归检查后推送；不将已有的无关工作一并暂存或提交。
- 遇到无法运行的检查，要记录命令、阻塞原因和风险，不能把它静默视为通过。

## 文档同步

- 大的功能进展、路线图变化和新技术债更新 `docs/roadmap.md`。
- 产品边界、主要平台和持久化策略的改变先更新 `docs/product-direction.md`。
- 有现实替代方案的长期架构选择写入 `docs/decisions/`。

## 上下文恢复

对话上下文可能被压缩，开发者不应仅依赖对话记忆。恢复工作前依次检查：

1. `git log --oneline --decorate -n 20`
2. `git status --short` 与与当前任务相关的 diff
3. `docs/product-direction.md`、`docs/roadmap.md` 和相关决策记录

## 与用户沟通的时机

在以下情况先讨论再扩大实现范围：

- 发现新的主要使用场景或可能改变 MVP 优先级的需求。
- 在本地/云端、数据保留、UI 技术、识别/翻译服务等方面需要不可逆或昂贵的选择。
- 工作段完成时，说明设计结构、实现范围、验证结果、已知风险和下一步建议。
