# 波形在素材边界重复读取

日期：2026-10-27。源码已修复，原生安装包尚未更新。

## 现象与原因

生产构建的合成混合负载预跑发现：播放头停留在窗口左侧 12% 时，首轮约三秒产生 183 次 get_waveform_window，后续三轮累计 365／549／730 次。每轮包括任务打开、播放、滚动、搜索、文字保存、工具开关和离页，使用独立合成 IPC／静音，没有真实文件或网络请求。

updateKaraokePosition 每次发现播放头靠近窗口边缘便请求重新居中。editor-waveform 会把期望起点限制在 0 至 duration−window 区间；播放头位于素材起点时，居中结果仍为同一窗口，接受返回后下一帧再次请求。短素材整段已经落在同一窗口、以及长素材末尾亦存在相同边界。原请求代次与合并只能防止旧返回覆盖，无法阻止连续帧重复提交同一个不可移动窗口。

## 修复与证明边界

waveform-follow 纯函数先按原 12% 边缘规则判断，再计算与实际加载一致的居中、四舍五入和素材范围限制。只有新起点能够变化时才请求；位置不变继续绘制当前播放头。没有给显式 resize、平移或缩放加全局缓存，点数改变仍能重新读取。

两项单元回归覆盖起点／末尾／短素材、正常边缘居中、视窗外跳转及内部位置。WebKit 用生产构建与真实 audio 播放分别验证短素材整窗首尾、三小时声明时间轴的起点，持续播放不产生逐帧请求；20 秒静音不等于三小时媒体解码验证。混合负载的完整测量范围与结果见[性能记录](editor-performance-validation.md)。

修复未重建原生 App，不从合成 IPC 的请求数量外推后端 IO、滚动 P95、真实媒体或内存改善。
