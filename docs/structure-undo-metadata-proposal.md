# 结构撤销的元数据范围：审计与待确认方案

日期：2026-10-25。状态：proposal，未采纳、未改变运行时行为。继承 [0047](decisions/0047-ui-themes-and-candidate-retention.md) 的会话内结构历史与学习快照边界；本提案不是模块搬移，也不作为既有事务已完整恢复的证明。

## 已确认的问题

2950a6d 原生验证证明 cue ID、顺序、文字、时间与编辑标记可恢复，但被删 legacy cue 的来源改为 structural／stale。新增 SQLite 隔离回归进一步通过真实候选采用、删除及撤销方法验证：

- 采用过的 cue 恢复后丢失 source_run_id 和 timed_unit_ids，来源为 structural／stale，原 source_revision=7／translation_revision=3 重置为 0／0。
- 原三条翻译依赖只剩不触及被删 cue 的一条；被删块作为目标和上下文的两条边都未恢复。被影响机器译文的 translation_stale 随 cue 快照恢复为 false，之后修改恢复块的原文也不能触发该消费者的上下文过期标记。
- 学习收藏保留文本／时间快照，segment_id 仍为空。这符合既有“解除后不推测重新关联”的范围，不应顺手改成按文字或时间匹配。
- ASR run、合成证据文件和采用台账保留，asr_run_is_protected 仍为 true。没有证据表明本次操作删除了采用证据，但证据受保护不等于 cue 来源关系已恢复。

原因是 restore_segment_structure 只接收 before／after cue。删除的外键级联已移除 provenance 和相关依赖；恢复时 persist_structure_segments 只能保留当时仍存在的关系，无法从 cue 文本反推旧元数据。当前前端历史仅保存 cue 数组，补一个视图回调不足以解决。此缺口发生于人工结构操作后的撤销，不是此前 ASR 接缝丢句的原因。

证据为 `src/infrastructure/local_db/structure_undo_scope_tests.rs` 的现状刻画测试；其丢失断言用于复现问题，修复时必须替换为目标合同，不能将它当作期望行为。共享库 159 passed／5 环境依赖 ignored。全部使用唯一临时目录、合成 run／文件，未运行识别或翻译；没有修改正式或 QA 数据。摘要与日志在忽略目录 `local-artifacts/editor-undo-scope-audit-20261025/`。

## 推荐：完整恢复来源与翻译依赖

将结构撤销定义为恢复 cue 及对应的来源／翻译依赖语义。学习收藏继续沿用现有快照规则，不自动重连已解除的引用；ASR 采用台账、人工审查和原始证据保持追加保护，不随撤销删除历史。

建议由后端在实际写入的同一事务中捕获完整 before／after 状态，返回不透明的会话 undo token 与字幕结果。前端现有唯一结构历史改存 token／标签，不再保留另一份完整元数据历史；后端只在当前 App 会话持有有界快照。避免“先读取元数据、再独立提交”留下竞态，也避免让前端提交可伪造的 ASR 来源字段。

恢复在一个 SQLite 事务内完成，并比较 expected workspace revision 和实际 after 状态；新文字、翻译、结构或其他相关元数据提交后，旧 token 必须拒绝。workspace revision 保持递增，重建 cue 的 revision 不能倒退／复用旧值；恢复依赖边时将引用修订号映射到新修订号，防止旧后台结果因计数归零而重新符合校验。来源的 run／timed-unit 身份按已捕获、已校验的记录恢复，不用文本推断或字符插值。

按用例逐步扩展编辑服务和 IPC，兼容现有调用者；不在一次机械模块抽取中重写事务，不改字幕 schema、导出格式或源译对应。会话 token 的十条任务上限、跨任务保留及总内存预算需一起验证；预算值用 10,000 段素材测量后确定，原始媒体／模型／ASR 大文件不进入撤销快照。

实施拆分：先新增事务内状态捕获与冲突／回滚测试；再逐个结构用例接入同一 token 历史，替换原数组历史；最后验证删除／Join／候选采用及连续撤销、迟到翻译拒绝、过期传播、重启失效和内存释放。每步单独提交，不并行维护两套可用编辑历史。

验收必须同时核对 cue、来源身份、依赖集合与修订映射，覆盖中途 SQL 失败完整回滚、旧 token 拒绝及后续上下文编辑仍能标记消费者过期；不能只比较字幕文本或表行数。

## 较小方案：内容撤销加保守失效

继续只恢复 cue，明确展示来源已脱离，并捕获被影响的机器译文集合，在恢复时保持其待复核／过期，直到显式重译重新建立依赖。仍需补后端状态和事务测试，不能仅加一条提示后继续把缺失依赖的译文显示为最新。优点是合同改动较小；代价是撤销后需要额外复核／重译，不能恢复原有来源可追溯性，且不能通过全片失效替代精确影响集合。

建议采纳完整来源与依赖恢复。是否实施属于会话历史／接口合同的实质调整，先由用户确认；在此之前只提交审计、现状回归和提案，其他既定编辑器验收可继续。
