# 三档生产 WebKit 对照：df5aa24 与当前编辑器

日期：2026-10-29。性质：验收证据。实际 Tauri 窗口、三小时媒体和内存结果另见[性能记录](editor-performance-validation.md)，不能与本报告串成一次相同 workload 的原生测试。

## 方法与边界

同机使用 Playwright 1.62.1／WebKit 26.5、1180×760 视口，分别加载两版生产 bundle。基线为计划指定 df5aa24；当前产品代码对应 778d936，记录时主树 HEAD 744d4ad 的后继差异仅为文档。每个版本／规模新建浏览器会话，按规模交替版本先后顺序；每个会话包含三次事件窗口，不是三次独立冷启动或随机重复。

[对照工具](../scripts/measure-editor-version-pair.cjs)复用相同合成 IPC／字幕文本、20 秒静音和三小时时间轴声明；未调用真实 SQLite、媒体服务、模型或云端。冻结两版源码提交、生产文件 SHA，确认 preview index 匹配记录，结束时再次核对 bundle 未变。因此可以比较这些前端页面的规模行为，不能推导真实三小时解码、后端证据读取耗时或原生启动 TTI。

打开时间为首次任务卡片 click 到可编辑字段已观察、再经过两帧回调的时间，包含自动化观察和旧版额外的“字幕校对”导航，不是纯渲染时间或严格 TTI。搜索测量合成 input 事件到两次帧回调；输入 dispatch 不包含真实键盘／IME。保存观察值包含既有 650 ms debounce、页面回调及合成 IPC，不能当作 SQLite 写入耗时。当前 WebKit 的 Long Tasks API 不可用，结果为 unavailable／null，不能记成零长任务；低于计时分辨率的 dispatch 读数也不能当作零成本。

当前版三档初始均为 14 个摘要行，旧版分别为 300／3,000／10,000 个输入卡片。完整文字保留在当前段原译文框，搜索复用同一虚拟列表。

选择性搜索最后一句，两版均精确命中一个结果；广泛搜索“第”，旧版新增 300／3,000／10,000 个结果按钮，当前仍仅渲染 14 行。万段选择性／广泛搜索的事件至两帧观察值为旧版 3,746／3,882 ms、当前 15／31 ms；300 段广泛搜索为 27／31 ms，没有小数据搜索更快的证据。

三次滚动都先在恢复原 CSS 行为的前提下瞬时定位到 40%，经过多帧确认位置稳定，再 hover 容器。公开 mouse.wheel 会先准备滚动状态并等待 rAF；采样在真正 trusted wheel 事件回调才开始，排除这段驱动准备。每次一个 840 px 输入，逐次核对 trusted 事件及实际移动距离，随后以页面 timer 请求两秒观测。两版布局／信息密度不同，固定物理输入不是固定经过相同 cue 数，也不隔离某一项代码优化。

300 段基线三个窗口 P95 为 17／18／17 ms，当前均 17；3,000 段为基线 23／23／26、当前 17／18／17；万段为基线 160／2,055／49、当前 17／18／17。万段基线波动显著，其中一次页面 timer 约 5,689 ms 才结束请求的两秒窗口；完整帧数、窗口时长和事件至首次回调延迟均保留。只可认为本次大列表前端诊断改善，不能把中位数外推为稳定帧率保证或原生呈现结论。

两版三个规模均只保存一次、保留原首行节点。旧版这条普通文字保存路径本来就是局部 DOM 更新，不能归因成“从全表重建改为局部更新”。万段输入至在 mock 检测到保存的观察值约 13,027／664 ms，受 debounce 和观察回调影响，不能当作真实写入对照。每次保存后再静置约 2.2 秒，旧版均调用一次 list_jobs，当前没有轮询调用；真实轻量摘要接口和证据校验成本仍由后端及原生验证证明。

## 采集修正与证据

最初串行 60 次滚轮的探索协议有两个问题：300 段准备动画未停止，实际移动 6,583 px，不能与当前 840 px 比较；Playwright WebKit 每次滚轮前的滚动状态／rAF 准备也被混入窗口。该批六案例最终自然完成，没有发终止信号；尝试终止检查时原浏览器 PID 已不存在，保护断言阻止了操作。原批数据和源码保留为 superseded，早先 3,000 段的 386 ms 不用于最终结论。修正后 300 段先预检，再完整重跑六案例，不能择取旧协议数字与新协议拼接。

最终六案例、18 次窗口全部通过事件／距离、源文件／生产包、搜索命中、单次保存／节点保留检查，无 pageerror；结束后受控 WebKit runtime 进程为零，两台 preview 服务已停止。每案例有 180 秒资源截止，未触发。原始结果及分析检查在忽略目录 `local-artifacts/editor-browser-pair-event-20261029/`；前两次预检及被取代协议分别单独保留，没有覆盖失败或探索证据。

本次只新增测量工具与记录，正式 App 28e2909 未改动。原生同负载滚动基线仍受输入／AX 工具限制，真实启动 TTI、原生长任务及首次实际加载暂态也未由本报告关闭。

## 复现入口

先构建并以两个本机 preview 服务提供 df5aa24 与当前生产包，从主项目根目录运行 `scripts/measure-editor-version-pair.cjs`。设置 `ATOGAKI_BASELINE_ROOT` 为历史 checkout 的绝对路径，`ATOGAKI_BASELINE_URL`／`ATOGAKI_EDITOR_URL` 为两个本机端点，`ATOGAKI_PLAYWRIGHT_MODULE`／`PLAYWRIGHT_BROWSERS_PATH` 指向已准备的 runtime，并用 `ATOGAKI_EDITOR_QA_OUTPUT` 指定新的证据目录。默认三档全部运行，`ATOGAKI_PAIR_COUNTS=300` 可做预检；工具拒绝覆盖已有 results.json，每案例有截止，结果记录生产 hash 与阶段。

完整量化的原执行源码以 recorded-tool.cjs 保留并与启动 hash 一致；主树交付版只将机器专属 baseline 默认路径改为必填环境配置，测量逻辑相同。未配置时必须在创建输出或启动浏览器前拒绝，避免静默读取错误 checkout。
